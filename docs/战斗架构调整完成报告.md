2. **最小兼容方案**

沿用 BattleRoundManager、RunManager、卡牌运行器的单位登记集合及现有地图/结算界面，没有新增重复 Manager、Round 或玩家 HP 副本。按后续明确的流程，每轮先结算存活单位 HP 伤害，再清空双方单位；幸存征召牌进入弃牌堆，清场不触发死亡效果。下一轮敌阵在准备阶段提前刷新并待机，玩家重新出牌部署后点击开打。

3. **旧主堡处理**

正式战场完全移除 PlayerBase 节点、初始化、死亡信号与清場胜负连接；最低生命及最近敌人索敌不再回退到建筑。旧场景、美术文件保留，脚本变为不参与战斗的兼容壳。选择/索敌中的 player_base 过滤仅用于防止旧资源误入战斗，不是攻击规则。

4. **玩家 HP**

唯一来源为 `RunManager.hp / max_hp`，战斗只提供只读访问。只在新 Run 按 RunStartData 初始化，进入下一节点不恢复。hp setter 将生命钳制至0与最大值之间；战斗期间归零立即进入失败。

5. **敌方 HP**

`BattleLevelConfig.enemy_max_hp` 默认45；进入节点复制到该战场的 `BattleRoundManager.enemy_max_hp / enemy_hp`。不写入 Run，新节点独立恢复配置生命。

6. **Round 与状态**

唯一轮数在 BattleRoundManager.current_round，正常从1开始，完成结算且双方 HP 存活才进入下一轮。状态区分准备、玩家阶段、交锋、回合结束、伤害结算、下一轮、胜利、失败；沿用 Global.GamePhase 通知单位与卡牌。

死亡或退场只提交检查请求，同帧多次请求合并到延后检查。进入结算前锁定状态；尸体即使还在播放动画也不算存活。回合末先结算毒和连锁爆炸，再同时查询双方，避免同时全灭时受数组顺序影响。

7. **回合伤害**

唯一计算入口 `calculate_round_hp_damage(round_number, surviving_units)`：轮数 + 胜方全部正式活单位 hp_damage_value。双边全灭为平局，双方不扣 HP。暴露总伤害、轮数贡献、单位贡献及结算信号，UI 显示上一轮伤害组成。

8. **单位配置**

全部21份 UnitData 资源显式写入 hp_damage_value，运行时不按名字判断。当前骑士 knight 与圣殿骑士 knight_templar 为3，弓箭手 archer 与骷髅弓箭手 skeleton_archer 为2；其余为1，策划可在 Inspector 调整。

资源清单：archer、armored_axeman、armored_orc、bat、elite_orc、greatsword_skeleton、knight、knight_templar、lancer、necromancer、orc、orc_rider、priest、skeleton、skeleton_archer、slime、soldier、swords_man、were_bear、were_wolf、wizard（均在 data/units，后缀 .tres）。召唤物只要进入正式集合且仍活着，也计入结算。

9. **能量计算**

`BattleRoundManager.calculate_energy()`：基础值 = min(首轮能量 + (Round-1) × 成长, 基础封顶)。默认3、1、10，因此 Round8 已达10。最终上限 = 基础值 + 附加效果，下限0，没有最终10点硬上限。每轮开始回复最终上限。

10. **未来遗物、卡牌和状态扩展**

整局永久加成保存在 RunManager.bonus_energy_max，开局值来自 RunStartData。遗物可选 MAX_ENERGY，统一通过 add_relic 获得；效果跨节点保留。

本场上限效果调用 `add_energy_modifier(source, amount, start, end, period)`，source 按 permanent → relic → card → status 计算。amount 支持负数，end=0表示持续本场，period=3表示每三轮生效。例：首轮+2用(1,1)，下一轮-1用(当前轮+1,当前轮+1)。准备中修改分母不额外回满。

即时能量使用 gain_energy(+3)，可以超过当前分母但不修改基础值；旧 ENERGY_EACH_ROUND 仍从下一轮增加本场持续附加能量。没有重写卡牌或遗物系统。

11. **胜利与失败**

敌方 HP 归零调用原 finish_battle(true)，玩家 HP 归零调用 false。原 GameOver 继续按钮与 GameSession 地图完成/失败返回菜单流程保留。结束后锁住状态、停止旧计时器、取消弹道/召唤/药水，拒绝卡牌、回合推进及旧伤害。节点完成仍由现有“继续”按钮确认，不擅自新增奖励流程。

12. **旧系统冲突与处理**

- 旧倒计时不再结束交锋。Battle Duration、round_duration_bonus 和计时器入口仅保留加载/工具兼容。
- 时长牌没有新的合法作用，拒绝施放且不吞牌/扣费，并从正式初始牌组移出；资源保留。
- 城防铁壁属于旧建筑防御，无法套进文档的精确 HP 公式，因此拒绝获得；旧枚举及资源保留。坚城之心继续增加玩家最大/当前 HP。
- 有限波次耗尽不再代表胜利，重复最后有效阵型直到 HP 归零。空项仍不刷新，当场空阵容可按新规则平局或失败。
- 双方都仍有单位时不触发回合末毒；毒沿用回合末规则，改在全灭结算时触发，没有擅自添加中途毒计时。
- 不改变寻路、地图生成、攻击属性、存档和动画资源。

13. **Godot 手动配置**

无需补节点、接信号或配置 Autoload，代码和场景已接好。F5 可直接新开一局。策划可以修改 RunStartData.max_hp/starting_hp、各关卡 Enemy Max Hp、首轮能量/成长/基础上限及 UnitData.hp_damage_value。F6 单独战场使用默认敌方45 HP与3/1/10能量；地图进入时读取关卡 .tres 配置。
