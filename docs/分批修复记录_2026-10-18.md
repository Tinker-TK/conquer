## 第一批：启动、单位生命周期与回归门禁

覆盖 P0-2、P0-3，及 P1-7/P1-13 中与此相关的最小修复。

### 已实施

1. **安全测试入口与启动检查**
   - 整局烟测的实际逻辑移到 Node 用例，在 autoload 完成后加载，避免启动主脚本提前解析 CardInstance 导致 Global 编译失败。
   - 旧 `tests/game_session_smoke.gd` 命令入口保留为通用启动壳的薄包装。
   - 新增独立 RuntimeGuard，不引用 Global 或领域类型；检查脚本型 autoload 和阶段接口，不可用则输出启动诊断、暂停并退出。
   - 未知 regression 参数退出 2。公共入口 watchdog 使用 `Time.get_ticks_usec()`，不受游戏暂停、倍速或 `--fixed-fps` 模拟时间影响。

2. **外部进程日志与时长保护**
   - 新增公共 `godot_process.py`，持续读取固定大小输出块；不再无限捕获到内存。
   - `run_checks.py` 默认每项真实时长 60 秒、控制台与文件日志合计 16 MiB；检测脚本/引擎错误后立即结束对应进程。保留原来针对系统证书存储错误的精确例外。
   - 文件日志同样监控；轮询可能短暂超过阈值，进程结束后会保留有限的首尾内容，确保两份持久日志合计不超过预算。
   - 每次运行使用不同活动日志名和用户目录，结束后原子替换常用报告，避免并发同名检查互相截断文件。
   - 新增受保护的开发启动器 `run_game.py`，默认 30 分钟、16 MiB，支持项目外输出；原生编辑器 F6 不经过这个外部启动器。
   - 混合天气用例显式记录 `status=partial` 和 GPU skip；图形分支可用 `--graphical` 单独运行。

3. **单位生命周期**
   - `current_health: int = 0`；首次入树时先复制配置和设置生命，换父节点时保留既有生命与运行数据。
   - 先记录战场归属，单位 ready 完成后才登记卡牌与战术状态。统一 `is_alive()` 用于活单位查询、留存、战术阵容及回合 HP 伤害。
   - 无 UnitData、非法阵营/最大生命或缺必需节点的单位只报告一次、停用并回收；技能/导航 ready 避免继续解引用无效数据。
   - SkillManager 幂等补连 frame_changed：旧场景不会重复触发，新场景漏连时可自动补接。

4. **原有失败回归修正**
   - buff 按效果身份查找剩余期限，不再假定说明数组第一项是临时强化。
   - 状态布局用例纳入士兵现有剑矢被动；悬停按图标身份定位，保留顺序、换行与缩放断言。
   - 跨回合用例确认被打断技能的冷却仍保留，等待真实冷却结束再验证移动与新动作；未改游戏冷却规则。
