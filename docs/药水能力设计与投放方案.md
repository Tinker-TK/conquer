# 药水能力设计与投放方案

> 从 4 瓶范围伤害，扩成 40 瓶能让玩家做取舍的肉鸽消耗品。
>
> 版本：v0.1 设计稿  
> 适用：当前 Godot 工程 `ballsprite`，三幕征途  
> 范围：只做设计与投放方案，**未修改任何现有资源或脚本**  
> 基线：`data/potions/` 4 瓶、普通战斗 25% 掉落、商店 3 瓶、药水无上限、仅交锋阶段可用

**怎么读**：想先看内容 → 第 3 节图鉴；想先看规则和投放 → 第 4–5 节；准备开工 → 第 8 节；调平衡 → 第 9 节。

---

## 0. 一页结论

- **问题不是“少”，是“同质”**：现有 4 瓶全部是“选落点 → 范围直接伤害”，再加 10 瓶伤害瓶，玩家仍会觉得内容没变。
- **40 瓶 = 13 普通 + 17 稀有 + 10 传说**：现有 4 瓶保留数值，只补稀有度、价格和幕数标签。
- **每瓶一个“动词”**：伤害、控场、减益、增益、资源、召唤、规则破坏；不做“更大的火焰药水”。
- **三条规则改造**：3 格药水带（可扩到 5）、即时药水不占“生效中”槽、准备阶段可用非伤害药水。
- **六个获取口**：战斗 35%、Boss 100%、商店 3 瓶、事件三选一、篝火调配、开局 1 瓶（可选）。
- **六条构筑轴**：毒/回合末爆发、聚怪爆发、召唤送死、防守续航、资源爆发、控制链；配套 4 件遗物、4 个事件、2 张卡。
- **分四批上线**：12 → 20 → 32 → 40 瓶。第一批只复用现有系统，3–5 天就能看到“不再只有伤害瓶”的变化。

## 1. 现状：为什么玩家觉得药水很少

| 维度 | 当前实现 | 玩家感受 |
| --- | --- | --- |
| 数量 | 4 瓶：火焰、闪电、龙卷风、雷云 | 每次商店和奖励都在同一个小池里抽，重复感强 |
| 功能 | 全部是“选落点 → 范围直接伤害” | 没有解场、抽牌、召唤、复活、成长等功能位 |
| 获取 | 普通战斗 25%；商店 3 瓶；随机药水事件 | 一场战斗平均掉落约 0.25 瓶，商店还只卖 4 种 |
| 库存 | `RunManager.potions` 无上限、无丢弃 | 不需要取舍，“屯着”没有代价 |
| 使用 | 仅交锋阶段；一次一瓶，效果结束才能用下一瓶 | 不能连续喝，节奏偏慢，救场感弱 |
| 稀有度 | 无 | 没有“哇，这瓶是传说”的惊喜 |
| 定价 | 45 / 55 / 65 / 80 金 | 与强度不完全对应：雷云 3 回合持续输出，80 金明显偏便宜 |

**结论**：只扩数量，不扩功能，药水仍然只是“额外伤害”。真正要补的是**功能位、稀有度、库存取舍和获取随机性**。

## 2. 设计原则

杀戮尖塔的药水之所以有肉鸽感，不是因为瓶数多，而是因为五个约束：**3 格腰带、使用窗口灵活、一次性、稀有度随机、Boss 前留瓶**。本文按这五点改造本作；其中“使用窗口灵活”翻译成“准备阶段可用非伤害类，交锋阶段全部可用”。

### 2.1 要的肉鸽感

1. **一瓶一个动词**：聚怪、冻结、抽牌、复活、策反、跳过本轮。玩家记住的是“这瓶能干什么”，不是“这瓶打多少”。
2. **稀缺产生取舍**：药水带 3 格，满时必须替换；Boss 前留一瓶还是现在救场，是核心决策。
3. **稀有度制造惊喜**：普通保底、稀有改变一波、传说改变一局；掉落权重按幕递增。
4. **药水是爆发和救场，不是引擎**：卡牌和遗物负责长期成长，药水负责“这一回合翻盘”。不能取代卡牌。
5. **组合要显而易见**：重力井 + 陨石、泥沼 + 火焰、诱饵 + 链电。玩家第一次看到就能理解。
6. **每瓶都有使用时机和反制**：催眠不能接毒、圣盾不能留到下一轮、陨石会被位移躲开、烟雾弹对 Boss 无效。

### 2.2 不要做的

- **不要“大号火焰药水”**：+20 伤害的同质瓶只会稀释卡池。
- **不要让 Boss 必须靠某瓶药水才能过**：药水是可选解法，不是门票。
- **不要用药水替代卡牌/遗物**：药水是一次性的，不该提供稳定的每回合收益。
- **不要做无限成长**：除“生命果实”这类限量传说，不做永久加攻/加防的滚雪球。
- **不要引入药水熟练度/经验条**：那会把消耗品变成第二套遗物系统，增加 UI 和理解成本。

## 3. 药水图鉴：40 瓶

### 3.1 阅读说明

- **目标**：落点、全体友军、自身、敌方单位、阵亡友军、随机友军、被动。
- **伤害**：除非特别说明，均为直接效果伤害，走 `take_effect_damage`，无视防御和闪避，与现有药水一致。
- **时间单位**：
  - **回合**：增益、区域。复用卡牌 buff / zone 的回合计时，显示“剩余 X 回合”。
  - **秒**：减益、硬控。复用 `UnitStatusRuntime` 的秒级计时。
  - **层**：中毒。回合结束时按层数结算，无视防御。
  - **本轮**：护盾、召唤。阶段切换时清除。
- **中毒的实际节奏**：层数不会自动衰减，但每轮结束会清场，所以毒只对当前这批敌人生效，实际上是“本轮末爆发”，不是跨回合 DoT。文案不要写成“每回合持续掉血直到战斗结束”。
- 所有数值都是**首版建议值**，不是最终平衡值。首版后用 10–20 场同策略对照再调。
- **校准锚点**：当前单位约 100 生命、玩家 80 生命（拿到坚城之心后 100）、每轮 5 张牌、能量 3 起每轮 +1、一次遭遇约 4–8 轮。药水数值按这个尺度定；如果之后单位生命或回合长度大改，需要同步重算。

| 诱饵 + 链电 / 火焰 | 先放诱饵 | 敌人围向诱饵，AoE 命中更多 | 诱饵只有 60 生命，别让它死得太快 |
| 能量 + 战术 + 智慧 | 先抽后喝 | 一回合多打 4–5 张牌 | 注意手牌顺序，战术只覆盖接下来 2 张 |
| 复活 + 亡语 | 先给亡语再复活 | 复活的单位再次死亡时仍会爆炸 | 复活是临时单位，本轮结束消失 |
| 烟雾弹 + 治疗 | 先跳过后回复 | 跳过必败波次，保留生命 | Boss 波无效；跳过后没有本轮奖励 |
| **反例：催眠 + 毒 / 火** | — | 持续伤害会打醒睡眠 | 想睡住就不要接伤害 |
| **反例：圣盾留到回合末** | — | 护盾在阶段切换时清除 | 圣盾要在交锋中、伤害到来前用 |
| **反例：陨石打空气** | — | 敌人提前全灭，陨石落地无目标 | 先确认还有目标，或用来压下一波出生点 |
| **反例：烟雾弹跳 Boss** | — | 设计上禁止 | 避免直接跳过 Boss 战 |

| **吸血药剂** `leech_brew` | 稀有 | 全体友军攻击吸血 30%，持续 2 回合 | 需要新增吸血状态；先让淬毒、亡语占住毒/召唤位 |
| **混沌之瓶** `chaos_flask` | 普通 | 随机触发 1 种已有药水效果 | 方差太大，更适合事件奖励，不适合商店常驻 |

## 4. 核心规则改造

### 4.1 稀有度

| 稀有度 | 边框色 | 建议价格 | 掉落权重（一幕 / 二幕 / 三幕） | 设计职责 |
| --- | --- | --- | --- | --- |
| 普通 | 白 / 灰 | 40–55 | 70 / 55 / 40 | 填充池子，提供稳定解 |
| 稀有 | 蓝 | 65–90 | 27 / 38 / 45 | 改变一波战斗 |
| 传说 | 金 | 110–150 | 3 / 7 / 15 | 改变一局走向，低概率惊喜 |

权重是“掉出一瓶药水时”的稀有度分布，不是总掉落率。Boss 按幕单独设权重：一幕 80 / 20、二幕 60 / 40、三幕 40 / 60，避免第一幕 Boss 反复给同一瓶生命果实。

### 4.2 药水带：3 格起步，最多 5 格

- 基础 3 格；遗物“炼金术士的腰带” +1；第三幕事件可再 +1；上限 5。
- 满格时，奖励/商店/事件获得新药水必须**替换一瓶或放弃**，不能自动丢弃。
- 同种药水可以叠加，显示 ×N；使用消耗一瓶，不合并效果。
- 丢弃：HUD 右键或长按药水图标，二次确认；丢弃无返还。
- 设计目的：让“带哪三瓶去 Boss”成为每幕末的核心决策。

### 4.3 使用时机

| 阶段 | 可用药水 | 说明 |
| --- | --- | --- |
| 准备阶段 `CARD_PLAY` | 非伤害类：增益、召唤、治疗、抽牌、能量、净化、成长、风险 | 让玩家先布阵再开打；伤害/区域仍限交锋，避免准备阶段空放和计时争议 |
| 交锋阶段 `AUTO_BATTLE` | 全部 | 主要使用窗口；救场、补刀、控场都在这里 |
| 结算 / 胜负 | 不可用 | 与现有规则一致 |

护盾类（圣盾药剂）仍限交锋阶段：现有 `add_shield` 在离开 `AUTO_BATTLE` 时会立即清除，准备阶段使用会直接消失。等护盾的清除规则改成“本轮结束”后，再放回准备阶段。仙女之泪是被动药水，不占用手动使用次数，满足致命伤条件时自动消耗。

### 4.4 生效槽：即时药水不再堵住下一瓶

当前规则是“一瓶效果结束后才能用下一瓶”，导致增益、抽牌、召唤类药水也被拖慢。建议改成：

| 类型 | 是否占用“生效中”槽 | 例子 |
| --- | --- | --- |
| 场地持续型 | 是，直到效果结束 | 火焰、龙卷风、雷云、泥沼、陨石燃烧 |
| 多段施放型 | 是，直到次数用完 | 闪电的 4 次落点 |
| 即时型 | 否，结算完立即释放 | 爆裂、寒霜、控制、增益、抽牌、能量、召唤 |

这样玩家可以“先喝能量，再喝战术，再喝智慧”打一波，同时保留“场上只能有一个持续区域”的限制，避免四个火圈叠在一起。

### 4.5 叠加与清理

| 类型 | 叠加规则 | 清理时机 |
| --- | --- | --- |
| 攻击 / 防御增益 | 同源加法叠加，持续时间独立 | 回合结束扣 1，到期撤销 |
| 护盾 | 数值相加 | 阶段离开交锋时清除 |
| 眩晕 / 睡眠 | 不叠加，取最长 | 时间到 / 受击苏醒 / 本轮结束 |
| 虚弱 / 破甲 | 加法叠加，虚弱上限 6，破甲上限 8 | 时间到 |
| 中毒 | 层数相加，无上限 | 回合结束按层数结算；清场后失效 |
| 减速 | 取最强，不叠加 | 时间到 / 离开区域 |
| 召唤物 | 每个独立存在 | 本轮结束清场 |
| 地面区域 | 每个独立，不覆盖旧区域 | 各自到期 |

### 5.3 事件

| **流浪炼金师** | 50 金买随机药水 / 2 瓶换 1 瓶稀有 / 离开 | 消耗金币或旧瓶，换更需要的瓶 | 给药水带腾位置，也给金币消耗口 |

### 5.4 篝火与开局

- **篝火“调配”**（可选，在“离开”前增加一个选项）：消耗 2 瓶普通药水，获得 1 瓶随机稀有；不足 2 瓶时禁用。它让“多余的普通瓶”有去处，也给篝火增加一个非战斗选择。现有事件选项没有“条件禁用”，要么给事件系统补这个能力，要么把它做成独立事件。
- **开局 1 瓶随机普通**：推荐开启，作为教学。当前 `RunStartData.starting_potions` 默认是空的，新玩家可能一整局都想不起来用药水。可在资源里加一个 `starting_random_potion: bool`，或在开局脚本里抽一瓶。

### 5.5 幕池：第一幕不要一次看到 40 瓶

用 `min_act` 控制每幕可用池，降低第一幕的理解成本，也让后两幕有新东西。

| 幕 | 普通 | 稀有 | 传说 | 合计 |
| --- | --- | --- | --- | --- |
| 第一幕 | 13 | 9 | 1 | 23 |
| 第二幕 | 13 | 17 | 7 | 37 |
| 第三幕 | 13 | 17 | 10 | 40 |

- 第一幕稀有：闪电、龙卷风、链式闪电、冰霜新星、圣盾、能量、战术、智慧、烟雾弹。
- 第二幕解锁稀有：腐蚀、催眠、混乱、重力井、淬毒、亡语、增援、锻造。
- 第一幕传说：生命果实（3% 低概率）。
- 第二幕解锁传说：雷云、陨石、时之静滞、仙女之泪、策反、血契。
- 第三幕解锁传说：复活、亡者军团、复制。

### 5.6 金币预算

- 开局 99 金；普通战斗 30 金 × 约 6 场 = 180 金；事件和宝箱约 30–60 金；一幕可支配约 300 金。
- 药水 45–90 金，占一幕收入的 15–30%。与卡牌 55–120、遗物 145–220 形成竞争。
- 目标：每次商店让玩家在“补一张卡 / 买一瓶药 / 攒钱买遗物”之间犹豫，而不是无脑买瓶。

## 8. 实现方案

### 8.1 数据模型

保留现有 `PotionDefinition` 的 4 个 `Kind` 和数值字段，新药水走“效果列表”，避免一次性重写旧资源。现有的 `Targets`（影响敌方/己方/双方）继续用于范围伤害；新加的 `TargetMode` 只决定 UI 让玩家选什么目标，两者不要混用。

```gdscript
# data/potions/potion_definition.gd
enum Rarity { COMMON, RARE, LEGENDARY }
enum TargetMode { POINT, ENEMY_UNIT, ALLY_UNIT, ALL_ALLIES, ALL_ENEMIES, DEAD_ALLY, RANDOM_ALLY, SELF, PASSIVE }
# 只在末尾追加，避免旧 .tres 的 Kind 整数被重新解释
enum Kind { TORNADO, LIGHTNING, FIRE, THUNDER_CLOUD, EFFECTS }

@export var rarity: Rarity = Rarity.COMMON
@export var target_mode: TargetMode = TargetMode.POINT
@export var tags: Array[StringName] = []
@export var min_act := 1
@export var max_act := 3
@export var price := 50
@export var prep_usable := false
@export var max_per_run := 0
@export var effects: Array[PotionEffect] = []
```

```gdscript
# data/potions/potion_effect.gd（新）
class_name PotionEffect
enum Kind {
    DAMAGE, DAMAGE_OVER_TIME, ZONE, STATUS, BUFF, SHIELD, HEAL_PLAYER,
    DRAW, ENERGY, SUMMON, CONVERT, COPY_ALLY, REVIVE, CLEANSE,
    UPGRADE_CARD, SKIP_ROUND, DELAYED_BLAST
}
@export var kind: Kind
@export var amount := 0.0
@export var radius := 0.0
@export var interval := 0.5
@export var duration := 0.0
@export var rounds := 0
@export var delay := 0.0
@export var status_id: StringName
@export var status_stacks := 1
@export var buff_kind: CardEffect.Kind
@export var unit_data: UnitData
@export var count := 1
```

**兼容原则**：

- `Kind` 只在末尾追加；旧 4 瓶继续用 `TORNADO / LIGHTNING / FIRE / THUNDER_CLOUD`。
- 新药水 `kind = EFFECTS`，读取 `effects` 列表；旧药水忽略 `effects`。
- 新字段全部有默认值，旧存档和新存档都能读。
- 不删除、不改名旧字段，避免现有测试和 `.tres` 失效。

### 8.2 执行流程

1. HUD 点击药水 → `BattleItems.begin_potion(potion)`。
2. 根据 `target_mode`：
   - `POINT / ENEMY_UNIT / ALLY_UNIT`：进入瞄准，左键选目标，右键/Esc 取消。
   - `SELF / ALL_ALLIES / ALL_ENEMIES / RANDOM_ALLY / DEAD_ALLY`：立即结算，不需要瞄准。
   - `PASSIVE`：HUD 只展示不可点，满足条件时由代码自动消耗（仙女之泪）。
3. `_activate(potion, target)`：先 `RunManager.consume_potion`，再交给 `PotionRuntime.cast`。
4. `PotionRuntime` 逐条执行 `PotionEffect`：
   - 伤害 → `unit.take_effect_damage`。
   - 状态 → `unit.status_runtime.apply_status`。
   - 增益 → 新增的 `CardBattleRuntime.apply_potion_buff`，**绕过** `_effect_for_current_phase` 的 1 回合降级。
   - 中毒 → 新增的 `CardBattleRuntime.add_poison`。
   - 召唤/复制/策反/复活 → 新增的公共入口，复用 `_prepare_unit`、`COPY_ALLY`、`tactical._convert`。
   - 抽牌/能量/玩家生命 → `HandManager.draw_cards`、`BattleRoundManager.gain_energy`、`RunManager.hp`。
5. 即时型结算完立即 `clear_effect()`；场地型和多段型保留“生效中”状态。
6. `PotionRuntime` 监听 `battle_round_ended` 和 `phase_change`，负责 buff 扣回合、区域到期、召唤清场、护盾清除。

### 8.4 分批上线

### 9.3 需要观测的指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 选取率 | 同稀有度出现时被拿走的比例 | 单瓶不超过 90%，不低于 10% |
| 使用率 | 获得的药水中实际喝掉的比例 | 60–80% |
| 屯瓶率 | 进 Boss 时仍带 2 瓶以上的局数 | 30–50%，不能 100% |
| 满格丢弃率 | 因满格放弃药水的次数 | 10–25%，说明容量有压力但不过分 |
| 单瓶价值 | 平均伤害/治疗/召唤折算 | 与同稀有度预算偏差不超过 30% |
| 胜率差 | 使用某瓶 vs 不使用的同策略对照 | 稀有瓶提升 5–10 个百分点，传说 10–15 |

## 附录 B：命名、文案与图标规范

- **ID**：小写蛇形，与文件名一致，例如 `frost_nova.tres` → `frost_nova`；不使用数字后缀。
- **名称**：3–6 个汉字，尽量带材质/动作，例如“寒霜瓶”“重力井”“血契药剂”；避免“超级药水”“高级药水”。
- **描述模板**：`目标 + 数值 + 持续 + 限制`。  
  例：`对范围内敌人造成 30 点伤害，破甲 4 点，持续 8 秒。`
- **禁止模糊文案**：不写“造成大量伤害”“显著提升”；写具体数字，改数值时同步改描述。
- **标签**：`爆发 / 持续 / 控制 / 减益 / 增益 / 资源 / 召唤 / 成长 / 风险 / 保命`。标签用于悬停和筛选，不参与玩法。
- **图标**：64×64、透明底、1 像素深色描边；稀有度边框由 UI 绘制，不画进图标。
- **颜色语言**：火焰橙、冰霜青、毒绿、奥术紫、神圣金、鲜血红。玩家应能在 0.5 秒内靠颜色判断功能。

## 附录 E：与现有系统的冲突清单

| # | 现有约束 | 影响 | 处理建议 |

## 结语

这 40 瓶不是“再加 36 个伤害数字”，而是 36 个**不同的战术动词**：拉、冻、睡、毒、抽、充能、召唤、复活、策反、免死。  
先把第 0 批 12 瓶做出来，玩家就会明显感觉“药水不再只是伤害”；等稀有度、药水带和事件到位，药水才会真正变成每局都能讲出故事的系统。
