# 卡牌强化与扩展设计

> 本文保留早期设计提案。2026-10-18已按用户确认表格实装27张牌；最终数值、吸血公式与配置字段以[卡牌效果说明](卡牌效果说明.md)为准。

对象：`data/cards/` 下的 27 张效果/能力牌（11 张征召牌走 `UnitData` 训练，不在本文范围）。

设计前提：**每张牌只能强化一次**（与《杀戮尖塔》一致），所以每次强化都必须是一次"看得见的跃迁"，而不是小步递增。

本文分两部分：

- **第一部分**：27 张牌各自的单次强化方案，含可直接填写的字段值。
- **第二部分**：基于现有框架还能出的卡牌类型，含样例卡、依赖的现成系统与开发量。

---

## 一页结论

1. **27 张牌全部只强化 1 次**，`max_upgrade_count` 统一为 `1`。其中 13 张老牌默认就是 1，只需填增量；另外 14 张现在是 0，要把 0 改成 1 再填增量。
2. **21 张只改资源数据**（`upgrade_amount`）就能生效；**6 张需要少量扩展**（3 个通用字段 + 2 处 `amount` 语义复用，约 30 行，见第 4 节）。
3. 单次强化的力度按《杀戮尖塔》的直觉定：**效果 +40%～60%，或 −1 费，或换一种用法**。有条件、有代价的牌可以给足；无条件常驻牌要克制。
4. 第一章一局最多经过 3 个篝火（第 4、6、9 层），而牌组通常有 12 张以上，所以"给哪张牌升级"是实打实的取舍。
5. 新增卡牌优先级：**① 状态牌 ② 交战期响应牌 ③ 消耗区回收/检索 ④ 楼层牌 ⑤ 献祭/复活 ⑥ 团队光环**。这六类都能直接复用已有系统，不需要重写战斗逻辑。

> 如果你想要的是《杀戮尖塔》里"升级后卸掉代价/多一条词条"的那种升级，第 4.5 节给了一个可选机制（强化时增删效果），可以只对 2–4 张牌使用，不影响上面的 27 张。

## 1. 先对齐：现在的强化是怎么跑的

### 1.1 代码路径

```
篝火/事件 → event_rewards.gd 筛出 can_upgrade(false) 的牌
          → CardInstance.enhance()
              definition = definition.duplicate(true)
              for effect in definition.effects:
                  effect.amount += effect.upgrade_amount
              upgrade_count += 1
```

> `max_upgrade_count` 是**每个卡牌实例**的上限，不是"每种牌的全局次数"：牌组里有 3 张力量强化，就能分别强化 3 次（和杀戮尖塔一致，同名副本是各自独立的牌）。

对应文件：

| 环节 | 文件 | 说明 |
| --- | --- | --- |
| 可强化次数 | `data/cards/card_definition.gd` | `max_upgrade_count`，0 为不可强化，默认 1 |
| 每次增量 | `data/card_effects/card_effect.gd` | `upgrade_amount`，可为负数 |
| 执行强化 | `scripts/cards/card_instance.gd` | `enhance()`，只改本牌副本 |
| 卡面文字 | `scripts/cards/card_description.gd` | 按当前 `effects` 实时生成 |
| 篝火入口 | `scripts/events/event_rewards.gd` | `enhance_card` 类型，列出可强化牌 |
| 存档 | `autoload/run_manager.gd` | 存的是**强化后的配方副本**，读档不重复叠加 |

### 1.2 数据能做 / 不能做

| 想要的强化 | 现有数据 | 需要什么 |
| --- | --- | --- |
| 数值变大/变小 | ✅ | `upgrade_amount` 可正可负 |
| 费用降低 | ❌ | 新增 `CardDefinition.upgrade_cost` |
| 范围变大 | ❌ | 新增 `CardEffect.upgrade_radius` |
| 持续回合变长 | ❌ | 新增 `CardEffect.upgrade_lasting_rounds` |
| 结算间隔变短 | ❌ | 新增 `CardEffect.upgrade_interval` |
| 追加一条新效果 | ❌ | 效果列表不随强化变化 |
| 改目标/类别/去向 | ❌ | 强化不改这些字段 |

### 1.3 单次强化的数值标尺

按现有卡面反推，1 点费用的量级大约是：

- +5 攻击（力量强化）／+2 防御（护甲加固）／回复 35% 最大生命（战地治疗）
- 1 次训练 = 3 点属性，永久作用于 1 张单位牌，每场可复用
- 防御点约等于 2.5 倍攻击点的价值（因为按次抵扣）

不同类型的绝对值差异很大（治疗与抽牌明显更贵），所以统一用**属性点**做标尺：

| 强化类型 | 单次幅度 | 例 |
| --- | --- | --- |
| 数值型 | 原效果 **+40%～60%**（至少 +1 个整数点） | +5→+9、20%→30%、30→45 |
| 费用型 | **−1 费** | 2 费 → 1 费 |
| 阈值/代价型 | 门槛或代价 **−1** | 6 费 → 5 费、阵亡加费 +2→+1 |
| 持续型 | **+1 回合** | 2 回合 → 3 回合 |
| 目标型 | 解锁更高一级目标 | 策反普通 → 策反精英 |

单体、一次性、要花能量的效果（力量强化、同生共死）可以取到上限以上，因为它们的收益受"抽到 + 花能量"双重限制；全队常驻效果则应该取在下限，避免一张牌决定整场。

### 1.4 三条设计原则

1. **一次强化要改变"带不带这张牌"**，而不是只让它强一点。因为一辈子只能升一次，升完就定型了。
2. **条件越苛刻，成长越可以给足**（同生共死、审判者、鸣金收兵）；无条件光环要收着给（保持距离）。
3. **不能破坏既有判定**：点数必须整数、百分比不超过上限、麻痹的间隔必须大于眩晕时长。

## 3. 逐卡解析

### 3.1 单体强化牌：一次升级就是一次质变

**1. 力量强化（+5 → +9）**
+80% 的增幅看着猛，但它是**单体、一次性、要花 1 费**的效果；对比训练（1 次 +3 攻击且每场复用），+9 才勉强对得起"一辈子只能升一次"。
注意：`ATTACK_UP` 走 `int(amount)`，必须是整数。

**2. 护甲加固（+2 → +3）**
防御按次抵扣，1 点防御约等于 2.5 点攻击，所以 +1 防御实际价值约 +2.5 攻击。+3 防御对多段攻击与群怪是质变，且不会像攻击那样被"打不到人"浪费。

**3. 战地治疗（35% → 50%）**
一次升级把"续命"变成"半次复活"：100 血单位上就是 50 点。它能救回一个即将阵亡的核心单位，从而改变整轮交锋的胜负。
风险：这是本批里最强的续航升级，若实测过强，回落到 45%。

**4. 淬毒武器（2 层 → 3 层）**
中毒无视防御、按命中次数触发。多段攻击单位（兽人连击、剑士三连）会把 3 层放大得很快，+50% 的实际收益往往高于面板。

**5. 同生共死（30 → 45）**
爆炸是"死后才收益"的条件性效果，升级后 45 点足以秒掉大部分前期小兵，让"送死"真正变成战术。

### 3.2 战术牌：一次升级换一个更硬的解法

**6. 镜像（2 费 → 1 费）**
复制单位本身已经很强，升级不该再加数值。降 1 费让它从"两回合一次的节奏点"变成"每回合都愿意留能量的选项"。
注意：`COPY_ALLY` 的 `amount` 不参与结算，加数值等于空强化。

**7. 狂化（吸血 120% → 150%）**
数据版只能涨吸血，因为 `amount` 同时被 `_on_attack_resolved` 当作吸血公式的配置值。120%→150% 意味着独狼形态下每点伤害都能回更多血，"一打多"的续航质变。
如果愿意加字段，也可以改成独狼三围 +70 / +40 / −25（见 4.1 的可选字段），更贴这张牌的玩法核心。

**8. 审判者（每击杀 +2 → +3）**
雪球牌，成长上限被击杀数天然限制。+50% 在长波次里足以滚起来，但前提是它真的能拿到人头。

**9. 易伤（20% → 30%）**
易伤在扣防御**之后**乘算，30% 已能改变"能否一刀斩杀"的判断。不可叠加，所以两张同名不会互相滚雪球。

**10. 虚弱（−2 → −3）**
可叠加，属于"多张一起打"的牌。−3 攻击对前期小怪已经很致命（`refresh_all` 会把攻击夹到 0）。

**11. 恐吓（−2 → −3）**
防御可以被压成负数，此时后续所有伤害都会额外增加。−3 能让大多数前期小怪防御归零甚至倒挂。

**12. 麻痹（1 秒 → 1.5 秒）**
眩晕占比 33% → 50%。`PARALYSIS` 不受整数限制，校验只要求 `interval > amount`（3 > 1.5）。
1.5 秒已经能打断一次完整的蓄力/冲刺，是"控制流"的关键升级。

**13. 策反（普通 → 精英，扩展）**
把目前闲置的 `amount` 解释为"可策反的最高怪物等级"：1 = 普通，2 = 精英。用它替换"再降 1 费"的常规升级，更贴合牌名，也直接复用 `UnitData.monster_rank`。
代价：精英怪通常自带技能，策反后是真收益，所以这张牌升级后的强度上限很高，是本次方案里最"爽"的一张。

### 3.3 能力/资源牌（含手牌操纵）：一次升级换一套循环

**14. 孤注一掷（抽 3 → 抽 4）**
禁抽是硬代价，抽得越多越值。+1 抽看起来不多，但它是 0 费牌，等于白送一张资源。
注意：`LOCK_DRAW` 是独立效果，升级时只给 `DRAW` 那条加增量。

**15. 血契补给（−4/+3 → −3/+4）**
两条效果同时升级：生命成本 −1、能量收益 +1，一升一降净赚 2 点资源。这是本批里"单次升级体感最强"的一张。
注意：`PAY_HP` 用负增量后仍是正数，校验的"总生命费用 < 当前生命"继续成立。

**16. 运筹帷幄（抽 2 → 抽 3）**
0 费、固有、起手、消耗，本来就是每场必到的牌；+1 抽等于每场多 1 张资源，而且是白拿的。

**17. 战术涌现（2 → 3 张）**
随机打出是纯免费价值。3 张已经能在一回合内铺开场面，配合 `孤注一掷` 会非常滚。

**18. 部队回撤（1 费 → 0 费）**
回撤是"再部署 + 保留原牌"的节奏牌，0 费才能和"收回再征召"的连招对上（也方便反复触发骑士这类上场效果）。
注意：`RECALL_ALLY` 的 `amount` 不参与结算。

**19. 鸣金收兵（+1 → +2 / 存活单位）**
翻倍型升级：4 个存活单位 = 下回合 +8 抽。这是本批里方差最大的一张，可能一次抽空牌库。
如果实测过强，把增量改回 +1（即保持原效果），只降 1 费会更稳。

**20. 烈焰灼烧（5/秒 → 8/秒）**
区域按 `interval` 秒结算，+60% 直接放大"卡位"收益。注意它同时烧**双方**，升级后站进去更危险，是纯粹的高风险高回报。

**21. 泥潭（2 回合 → 3 回合）**
减速已经封顶 100%（`MUD_ZONE` 校验不允许超过 100），所以唯一有意义的成长是"多困一回合"。3 回合的泥潭足以废掉一整波近战。

**22. 悼亡战意（+1 → +2 / 阵亡）**
翻倍型光环，配合 `不灭军势`、`同生共死` 的"送死流"，5 次阵亡 = 全体 +10 攻击。需要真的舍得送，属于构筑卡。

**27. 进化（1 费 → 0 费）**
进化是"把手牌变强"的引擎，0 费才能每回合都用，从而带动整套手牌流。
注意：`TEMPORARY_UPGRADE` 的 `amount` 不参与结算；另外 `can_evolve()` 要求目标牌还有强化次数——统一成"每张牌 1 次"后，进化对**所有未强化过的牌**都可用，比现在的可用面大很多。

### 3.4 常驻/阵容牌：一次升级决定这套牌能否成型

**23. 不灭军势（阵亡加费 +2 → +1）**
它的代价是"单位牌越打越贵"，升级直接削掉这个代价（降到与普通单位相同的 +1），比降价更贴合牌名，也让"留存流"真正可持续。

**24. 合理搭配（+2 → +3）**
需要 ≥3 种兵种，是"多兵种铺场"的奖励。+3 让阵容流有明确的成型号，也让"为了触发它而混兵种"的代价更值得。

**25. 保持距离（130% → 145%）**
全队生效的常驻增伤，是本次方案里覆盖面最大的升级。+15% 全队伤害 ≈ 每张单位牌都多练了半级。
**如果实测过强，改成 140%**，或者把近身端从 80% 提到 90%（需要新字段）。

**26. 战友（门槛 6 → 5）**
负增量在这里是"变强"：门槛越低越容易触发。配合 `不灭军势` 把单位牌涨到 5 费，反而更容易吃到 0 费减免，是一组天然联动。

### 3.5 强化后的卡面示例

卡面文字由 `card_description.gd` 自动重算，下面是几个容易出错的例子（按现有文案格式原样列出，`／` 表示换行）：

| 卡牌 | 强化后卡面 |
| --- | --- |
| 力量强化 | 使1名己方单位攻击力+9，持续本场战斗。 |
| 血契补给 | 消耗3点玩家生命。／获得4点能量，可超过上限。 |
| 战友 | 本场每打出费用≥5的牌，下张单位牌0费。／该单位牌回弃牌堆时恢复原费用，按普通规则加费。 |
| 泥潭 | 在指定位置生成半径250的泥潭，其中所有单位移动速度降低100%，持续3回合。／消耗。 |
| 不灭军势 | 本场战斗，己方存活单位保留至下回合；己方单位阵亡时，其征召牌费用+1。 |

## 4. 6 张需要扩展的卡

### 4.1 新增字段（推荐，约 30 行）

| 字段 | 位置 | 默认 | 含义 | 改动点 |
| --- | --- | --- | --- | --- |
| `upgrade_cost` | `CardDefinition` | 0 | 强化后基础费用 −N，最低 0 | `CardInstance.enhance()` |
| `upgrade_lasting_rounds` | `CardEffect` | 0 | 强化后持续回合 +N，仅 `ROUNDS` 生效 | `CardInstance.enhance()` |
| `upgrade_radius`（可选） | `CardEffect` | 0 | 强化后半径 +N | `CardInstance.enhance()` |
| `upgrade_status_seconds`（可选） | `CardEffect` | 0 | 强化后状态持续时间 +N 秒（方向 1 的状态牌用） | `CardInstance.enhance()` |
| `upgrade_interval`（可选） | `CardEffect` | 0 | 强化后结算间隔 +N 秒（通常填负值），不低于 0.1 | `CardInstance.enhance()` |
| `upgrade_solo_percent`（可选） | `CardEffect` | 0 | 狂化专用：独狼攻击/防御/冷却三围各 +N% | `CardInstance.enhance()` |

```gdscript
# data/cards/card_definition.gd，放在「卡牌效果」分组内
## 强化后本牌基础费用降低的点数，最低降到 0；0 表示强化不改费用。
@export_range(0, 10, 1) var upgrade_cost: int = 0
```

```gdscript
# data/card_effects/card_effect.gd
## 强化后给半径增加的像素；0 表示强化不改范围。同生共死、烈焰、泥潭可用。
@export var upgrade_radius: float = 0.0
## 强化后给持续回合增加的回合数；只在 Lifetime 为 ROUNDS 时生效。
@export_range(-9, 9, 1) var upgrade_lasting_rounds: int = 0
```

> 注意：**虚弱、易伤、恐吓、麻痹不要用 `upgrade_lasting_rounds`**。`tactical_effect_runtime.validate_effect()` 强制这四种战术效果必须 `lasting_rounds == 1`，改成 2 会被出牌校验直接拒绝。它们只适合改数值。

```gdscript
# scripts/cards/card_instance.gd  enhance()
definition = definition.duplicate(true)
definition.card_cost = maxi(0, definition.card_cost - definition.upgrade_cost)
for effect in definition.effects:
    if effect == null:
        continue
    effect.amount += effect.upgrade_amount
    effect.radius = maxf(1.0, effect.radius + effect.upgrade_radius)
    if effect.lifetime == CardEffect.Lifetime.ROUNDS:
        effect.lasting_rounds = maxi(1, effect.lasting_rounds + effect.upgrade_lasting_rounds)
upgrade_count += 1
```

### 4.2 两处"复用 amount"的小改

**策反：`amount` = 可策反的最高等级**

```gdscript
# scripts/cards/tactical_effect_runtime.gd  validate_effect()
if effect.kind == K.CONVERT_ENEMY and unit.unit_data.monster_rank >= int(effect.amount):
    return "策反只能转化该等级以下的敌军。"
```

`amount = 1`（默认）只允许普通；强化后 `2` 允许精英；`BOSS`(2) / `LEGENDARY`(3) 仍被拒绝。

**不灭军势：`amount` = 阵亡加费**

```gdscript
# scripts/cards/card_battle_runtime.gd  apply_effect()
CardEffect.Kind.RETAIN_ALLIES:
    retain_allies = true
    unit_discard_cost_increase = maxi(0, int(effect.amount))
```

`.tres` 里把 `amount` 设为 `2`（等于现有行为），`upgrade_amount` 设为 `-1`。

> **顺序很重要**：`undying_army.tres` 现在的 `amount` 是 `0`。如果先上代码、后改数据，`unit_discard_cost_increase` 会变成 0，等于白送一次强化。数据与代码请放在同一次提交里。
> 另外 `tests/undying_army_test.gd:86` 断言了 `not power.can_upgrade(false)`，开启强化后要改成 `power.can_upgrade(false)` 并补一次 `enhance()` 后的行为检查。

### 4.3 文案同步（只有 2 处写死）

`card_description.gd` 的 `_effect_text()` 里有两条文案是写死的，扩展后必须改成读字段；其余效果文案都会跟着数值自动变。

| 效果 | 现在 | 改成 |
| --- | --- | --- |
| `CONVERT_ENEMY` | 固定"普通敌方单位" | 按 `amount` 输出"普通/精英" |
| `RETAIN_ALLIES` | 固定"费用 +2" | `"费用 +%d" % int(effect.amount)` |
| `COMRADE` | 已用 `amount` ✅ | 无需改，门槛下降会自动显示 |
| 其余（费用、半径、回合） | — | 卡面费用图标与 `_duration()`/半径文字都会自动更新 |

### 4.4 兼容性

- 新字段默认值都是 0，老 `.tres` 不受影响。
- `enhance()` 只处理副本；同名牌、共享资源、编辑器里的原资源都不会被改写。
- 存档保存的是**强化后的配方副本**（`RunManager.create_save_data()` → `card_definitions`），所以费用降低会随存档保留，读档**不会重复扣减**（强化次数只用于显示和上限判断）。
- `scripts/battle/monster_test.gd` 的调试按钮会调用 `train()`，不涉及 `enhance()`，无需改。

### 4.5 进阶选项：让升级"改玩法"而不只是"改数字"

上面的方案全部是数值/费用/回合/目标的变化。如果想更接近《杀戮尖塔》里"升级后换一种用法"的手感，可以再加两个字段，让升级能**增删效果**：

| 字段 | 位置 | 含义 |
| --- | --- | --- |
| `upgrade_add_effects` | `CardDefinition` | 强化后追加到效果列表末尾的效果 |
| `upgrade_remove_effects` | `CardDefinition` | 强化后要移除的效果下标（从大到小删） |

```gdscript
# scripts/cards/card_instance.gd  enhance()，放在数值增量之后
var remove := definition.upgrade_remove_effects.duplicate()
remove.sort()
remove.reverse()  # 从大到小删，避免下标错位
for index in remove:
    if index >= 0 and index < definition.effects.size():
        definition.effects.remove_at(index)
definition.effects.append_array(definition.upgrade_add_effects.duplicate(true))
```

这样就能做出这些"去代价 / 加词条"的升级（每张牌仍只升一次）：

| 卡牌 | 现在 | 强化后 |
| --- | --- | --- |
| 孤注一掷 | 抽 3 + 本回合禁抽 | 抽 4，且**不再禁抽**（移除 `LOCK_DRAW`） |
| 血契补给 | −4 生命，+3 能量 | +4 能量，**不再支付生命**（移除 `PAY_HP`） |
| 力量强化 | 攻击 +9，本场 | 攻击 +9，**并回复 20% 最大生命**（追加 `HEAL_PERCENT`） |
| 悼亡战意 | 每阵亡 +1 | 每阵亡 +1，**并立刻抽 1 张**（追加 `DRAW`） |

代价与注意：

- 效果列表变化后，`card_description` 会自动重写文案（它本来就按 `effects` 生成），不用改 `card_discription`。
- `_validate_card()` 里有顺序约束：**收回单位、随机出牌必须是最后一条效果**，所以这两类牌只能"移除代价"，不能"追加效果"；一张牌也最多配置一次复制。
- 同一张牌里的所有效果共用卡牌的 `Target`，追加的效果必须也吃这个目标（比如 `HEAL_PERCENT` 追加到"己方单位"牌上才合法）。
- 存档保存的是强化后的配方副本，增删效果同样会随存档保留。
- 这段只建议对 2–4 张牌使用，否则"升级"会变成第二套卡牌系统，读卡成本变高。

## 7. 还能出哪些类型的卡

### 7.1 判断标准

一个方向值不值得做，看三点：

1. **框架里有没有现成的运行状态**（能复用就不新增系统）。
2. **它改变的是"怎么打"还是只是"数值更大"**。
3. **它能不能和现有 27 张牌产生组合**，而不是孤立强卡。

下面 10 个方向都满足前两条，**每张样例卡也都按"只能强化一次"给了基础值和强化值**。开发量最小的是方向 1、2、3、5、7；其中方向 3 的急救/掩护/死守可以零代码先上，打断要等方向 1 的状态入口。方向 4、6、8 需要新的位置/快照逻辑，建议放到后面。

### 7.2 十个方向

下面每张新卡也都遵守"只能强化一次"（`max_upgrade_count = 1`），表格最后一列写的是这次强化用哪个字段：

| 升级字段 | 来源 | 用途 |
| --- | --- | --- |
| `upgrade_amount` | 已有 | 加在 `amount` 上（伤害、护盾、点数、张数） |
| `upgrade_cost` | 4.1 | 费用 −N |
| `upgrade_status_seconds` | 本节方向 1 新增 | 状态持续时间 +N 秒 |
| `upgrade_radius` | 4.1（可选） | 半径 +N |
| `upgrade_add_effects` | 4.5（可选） | 追加一条效果（"并抽 1 张"这类） |

#### 方向 1：状态牌（控制 / 持续伤害）★推荐

**框架依据**：`scripts/units/unit_status_runtime.gd` 已实现 9 种状态
`bleed / confusion / mortal_wounds / sleep / stun / weakness / slow / taunt / armor_break`。
卡牌侧目前只用到 `tactics` 自建的虚弱、易伤、恐吓、麻痹四种；**流血、混乱、禁疗、睡眠、嘲讽、破甲这 6 种没有任何卡牌入口**（怪物的技能资源里有）。
另外泥潭的减速是直接改 `unit_data.speed`，并没有走 `slow` 状态。

**实现**：新增 `CardEffect.Kind.APPLY_STATUS`，字段：

- `status_id: StringName` —— 取上面的状态 id；
- `status_seconds: float` —— 持续秒数，0 表示本场；
- `amount` —— 强度（流血每秒伤害、破甲每次点数、眩晕秒数）；
- `upgrade_status_seconds: float` —— 可选，强化时给持续秒数加值。

`execute` 调 `target.apply_status(id, status_seconds, int(amount), null, "card_%d" % card.id)`。`source_key` 必须用卡牌实例 id，否则两张同名卡会互相顶掉。

**样例卡**：

| 卡名 | 费 | 基础效果 | 强化后 | 升级实现 |
| --- | --- | --- | --- | --- |
| 割裂 | 1 | 敌方 1 名：流血 6 点/秒，持续 8 秒（无视防御） | 流血 **9 点/秒**，持续 8 秒 | `amount +3` |
| 禁疗 | 1 | 敌方 1 名：8 秒内无法回复生命 | **12 秒**内无法回复生命 | `upgrade_status_seconds +4` |
| 破甲 | 1 | 敌方 1 名：每次受击防御 −1，本场可叠 | 每次受击防御 **−2** | `amount +1` |
| 沉睡 | 2 | 敌方 1 名：睡眠 5 秒，受击立即醒来 | 睡眠 **8 秒** | `upgrade_status_seconds +3` |

**开发量**：1 个 Kind + 状态 id 白名单校验。**搭配**：易伤、保持距离 → "增伤链"。

#### 方向 2：护盾 / 减伤牌 ★推荐

**框架依据**：`scripts/units/unit_base.gd` 已有 `shield_amount`、`add_shield()`、`receive_healing(overflow_to_shield)`，牧师和装甲斧手在用；**卡牌侧没有护盾入口**。护盾先于生命抵扣、交锋结束清除，规则现成。

**实现**：`SHIELD` Kind，`execute` 调 `target.add_shield(int(effect.amount))`。

**样例卡**：

| 卡名 | 费 | 基础效果 | 强化后 | 升级实现 |
| --- | --- | --- | --- | --- |
| 圣光壁垒 | 1 | 己方 1 名：+25 护盾（先于生命抵扣，交锋结束清除） | **+40 护盾** | `amount +7` |
| 溢流祷言 | 2 | 己方 1 名：本场该单位治疗溢出按 1:1 转为护盾 | 费用 **1** | `upgrade_cost 1` |
| 背水 | 2 | 己方 1 名：获得相当于已损失生命 30% 的护盾 | **45%** | `amount +15` |

**开发量**：低。**搭配**：战地治疗、牧师 → "盾流"。

#### 方向 3：交战期响应牌 ★推荐（几乎 0 代码）

**框架依据**：`Global.is_card_play_phase()` 同时允许 `CARD_PLAY` 与 `AUTO_BATTLE`；`card_battle_runtime._effect_for_current_phase()` 已经把交锋中的持续强化压成"本轮"。也就是说**框架本来就允许边打边出牌**，只是目前没有为它设计卡。

**实现**：0 代码，只需新卡数据（打断需要方向 1 的状态入口）。

**样例卡**：

| 卡名 | 费 | 基础效果 | 强化后 | 升级实现 |
| --- | --- | --- | --- | --- |
| 急救 | 1 | 立刻回复 1 名己方 25% 最大生命 | 回复 **35%** | `amount +10` |
| 掩护 | 1 | 立刻收回 1 名己方单位，其征召牌回到手牌 | 费用 **0** | `upgrade_cost 1` |
| 打断 | 1 | 立刻眩晕 1 名敌方 1.5 秒（打断咏唱/冲刺） | 眩晕 **2.5 秒** | `upgrade_status_seconds +1` |
| 死守 | 1 | 己方 1 名本回合防御 +4 | 防御 **+6** | `amount +2` |

**价值**：把"部署完看自动战斗"变成有临场决策，这是提升操作密度最便宜的一类卡。

#### 方向 4：楼层 / 地形牌 ★推荐

**框架依据**：四层地形 + 桥梁（`docs/四层地形与桥梁配置说明.md`）、高地每层 +10% 最终伤害（`unit_base.get_hurt()`）、`unit.set_floor()`、`is_flying`、按层隔离的导航与碰撞、`knockback_motion`。

**实现**：`FLOOR_SHIFT`（层数 ±1，`amount` 存附带伤害）与 `NO_KNOCKBACK`（本场免疫击退）。

**样例卡**：

| 卡名 | 费 | 基础效果 | 强化后 | 升级实现 |
| --- | --- | --- | --- | --- |
| 登高 | 1 | 己方 1 名立刻上移 1 层 | 费用 **0** | `upgrade_cost 1` |
| 坠落 | 2 | 敌方 1 名被推下 1 层，并受 10 点伤害 | 受到 **20 点**伤害 | `amount +10` |
| 坚守阵地 | 1 | 己方 1 名本场不再被击退 | 费用 **0** | `upgrade_cost 1` |

**开发量**：中（要处理可走区域与导航）。**价值**：把"地图"变成可操作资源，是这个项目最有辨识度的方向。

#### 方向 5：牌堆 / 消耗区操纵 ★推荐

**框架依据**：`hand_manager` 有 `draw_pile / discard_pile / exhaust_pile / active_cards`，`draw_locked`、`pending_bonus_draw`、`cost_increase` 都在用；但**没有任何"取回消耗区""检索""弃牌"效果**。

**实现**：3 个 Kind：`RETRIEVE`（消耗区 → 手牌，`amount` = 张数）、`TUTOR`（抽牌堆检索指定类别）、`DISCARD_DRAW`（弃 1 抽 N）。

**样例卡**：

| 卡名 | 费 | 基础效果 | 强化后 | 升级实现 |
| --- | --- | --- | --- | --- |
| 战地回收 | 1 | 从消耗区取回 1 张牌到手牌 | 取回 **2 张** | `amount +1` |
| 紧急动员 | 1 | 从抽牌堆检索 1 张单位牌到手牌 | 费用 **0** | `upgrade_cost 1` |
| 断舍离 | 0 | 弃 1 张手牌，抽 2 张 | 抽 **3 张** | `upgrade_amount +1`（加在 `DRAW` 上） |

**开发量**：低–中。**价值**：让"消耗"不再是单向，形成资源循环，是中后期续航的关键。

#### 方向 6：献祭 / 亡语 / 复活 ★推荐

**框架依据**：`ally_deaths` 计数、`_on_death()`、`unit.die()`、`board_cards`（单位↔原牌的绑定）、`DEATH_EXPLOSION`、`DEATH_ATTACK_AURA`。

**实现**：`SACRIFICE`（击杀己方单位换资源，`amount` = 能量）、`REVIVE`（本场阵亡单位返场，`amount` = 复活生命百分比）。

**样例卡**：

| 卡名 | 费 | 基础效果 | 强化后 | 升级实现 |
| --- | --- | --- | --- | --- |
| 献祭 | 0 | 击杀 1 名己方单位，获得 3 能量并抽 2 张 | 获得 **4 能量** | `amount +1`（加在 `SACRIFICE` 上） |
| 亡者归来 | 3 | 复活本场最早阵亡的 1 名单位（**50%** 生命），消耗 | 以 **75%** 生命复活 | `amount +25` |
| 殉道 | 1 | 常驻：本场己方单位阵亡时抽 1 张 | 抽 **2 张** | `amount +1` |

**开发量**：中（复活要记录阵亡单位快照）。**搭配**：悼亡战意、不灭军势、同生共死 → "死亡流"。

#### 方向 7：团队光环（全体而非单体）

**框架依据**：`DIVERSE_ARMY`、`DEATH_ATTACK_AURA` 已经是全体光环；`_apply_aura()` 遍历 `living_units()`，`tactics.refresh_all()` 支持可撤销贡献。

**实现**：`TEAM_ATTACK_UP` / `TEAM_DEFENCE_UP` / `TEAM_SPEED`，照抄 `composition` 光环结构（去掉兵种条件），`amount` 即加成值。

**样例卡**：

| 卡名 | 费 | 基础效果 | 强化后 | 升级实现 |
| --- | --- | --- | --- | --- |
| 战吼 | 2 | 常驻：本场全体己方攻击 +1 | 全体攻击 **+2** | `amount +1` |
| 坚守 | 2 | 常驻：本场全体己方防御 +1 | 全体防御 **+2** | `amount +1` |
| 疾行 | 1 | 常驻：本场全体己方移速 +20% | 移速 **+30%** | `amount +10` |

**开发量**：低。**价值**：铺场流的团队 buff，与 合理搭配 / 不灭军势 组成阵容构筑。

#### 方向 8：图腾 / 陷阱（场地单位与一次性区域）

**框架依据**：单位可设 `speed = 0`；`protection_aura`（圣殿骑士光环）已能给半径内友军加攻防；`zones` 数组可加 `triggered` 标记做成一次性陷阱。

**实现**：`SPAWN_TOTEM`（生成不可移动单位，`amount` = 光环加成）、`TRAP_ZONE`（敌方进入时触发一次，`amount` = 伤害）。

**样例卡**：

| 卡名 | 费 | 基础效果 | 强化后 | 升级实现 |
| --- | --- | --- | --- | --- |
| 战旗 | 2 | 在位置放置战旗（不可移动），半径 200 内友军攻击 +2，本场 | 光环 **+3** | `amount +1` |
| 地刺 | 1 | 在位置放置陷阱：敌人进入时受 15 伤害并眩晕 1 秒，触发后消失 | 造成 **25 伤害** | `amount +10` |

**开发量**：中。**价值**：让"站位"更重要，与 泥潭 / 烈焰灼烧 组成地形控制。

#### 方向 9：手牌操纵 / 变形

**框架依据**：`temporary_upgrade()`、`_evolution_snapshot`、`can_evolve()`、`next_unit_discount`、`free_until_discard` 已经在改手牌状态（进化、战友）。

**实现**：`DUPLICATE_HAND`（复制 1 张手牌）、`TRANSFORM`（手牌变形）、`HAND_DISCOUNT`（本回合手牌减费，`amount` = 减免点数）。

**样例卡**：

| 卡名 | 费 | 基础效果 | 强化后 | 升级实现 |
| --- | --- | --- | --- | --- |
| 誊抄 | 1 | 复制 1 张手牌（本场有效，退场不产生新牌） | 费用 **0** | `upgrade_cost 1` |
| 变阵 | 2 | 把 1 张手牌随机变成同费用的另一张牌 | 费用 **1** | `upgrade_cost 1` |
| 运筹 | 1 | 本回合手牌费用 −1 | 本回合手牌费用 **−2** | `amount +1` |

**开发量**：低–中。**价值**：combo 引擎，与 进化 / 战友 组成"手牌流"。
注意：复制手牌要排除"这张牌自己"，否则会无限复制自己；校验逻辑可以直接复用 `card_play_state.candidates()` 的写法。

#### 方向 10：能量节奏牌

**框架依据**：`BattleRoundManager.add_energy_modifier(source, amount, start, end, period)` 已支持起止回合与周期（`period = 3` 即每 3 回合），但**卡牌只能用 `ENERGY_EACH_ROUND` 和 `GAIN_ENERGY`**，没用上周期能力。

**实现**：新增 `ENERGY_MODIFIER` Kind，把 `start/end/period` 暴露到效果上，`amount` = 能量增量。

**样例卡**：

| 卡名 | 费 | 基础效果 | 强化后 | 升级实现 |
| --- | --- | --- | --- | --- |
| 蓄能 | 2 | 常驻：本场第 3、6、9… 回合开始时能量上限 +2 | 每轮 **+3** | `amount +1` |
| 透支 | 0 | 本回合能量上限 +3，下回合 −1 | 本回合 **+4** | `amount +1` |
| 节流 | 1 | 常驻：本场能量上限 −1，每回合多抽 1 张 | 费用 **0** | `upgrade_cost 1` |

**开发量**：低。**价值**：给费用曲线另一个构筑维度。

### 7.3 还可以考虑（成本更高）

- **诅咒 / 负面牌**：事件代价、Boss 机制。需要新增"不可打出"的卡类别与手牌规则，`RunManager.deck` 和牌堆视图能直接支持，但校验与 AI 需要改。
- **关键词化 / 条件效果**：把"消耗 / 常驻 / 固有 / 起手"做成卡面关键词，并新增"连击（本回合已打出 N 张则追加效果）"。`effects` 是顺序列表，但缺少条件判定，需要引入 `condition` 字段，改动面较大。
- **遗物联动牌**：读 `RunManager.relics.size()` 做"每持有一件遗物，效果 +1"。改动很小，但容易变成"雪球"，需要控制上限。
- **稀有度扩展**：目前只有 `COMMON / RARE`。`assets/ui_redrawn/components/` 已有红、蓝、绿、金四种卡框，缺紫色；加 `EPIC` 只需扩枚举 + 选框 + 奖励权重。

### 7.4 不建议做

| 方向 | 原因 |
| --- | --- |
| 天气牌（改变雨雪强度） | 天气目前是纯视觉系统，`scripts/units` 里没有任何天气耦合，做了没有玩法收益 |
| 水域 / 涨潮牌 | 动态河流只影响渲染与天气倒影，单位不读水陆，`is_water_point` 只被天气使用 |
| 真正的"敌方牌组" | 框架没有敌人手牌与出牌循环，等于重做一个战斗系统 |
| 直接给卡加"每回合自动触发" | 常驻区（`active_cards`）目前只在打出时结算一次，要做成遗物式触发器需要新的阶段钩子 |

### 7.5 建议的版本节奏

| 版本 | 内容 | 理由 |
| --- | --- | --- |
| 第一步 | 本文第 2–5 节：21 张数据强化 + 3 个字段 + 6 张扩展 | 统一"1 张牌 1 次强化"，让篝火选择立刻有取舍 |
| 第二步 | 方向 3（响应牌）+ 方向 1（状态牌） | 响应牌零代码起步，再接状态入口，直接提升对局操作感 |
| 第三步 | 方向 5（消耗区回收）+ 方向 7（团队光环） | 补资源循环与铺场流 |
| 第四步 | 方向 4（楼层牌）+ 方向 6（献祭/复活）+ 方向 8（图腾/陷阱） | 做出差异化玩法 |
