# ballsprite 数值分析框架与公式

日期：2026-10-08。适用范围：当前 Godot 项目的第一幕、征召卡与效果卡、自动交锋、波次、事件、遗物及药水。

这套框架已经使用引擎读取你的实际资源：21 个单位、54 个技能、15 张效果牌、7 件遗物、3 瓶药水、5 份关卡。公式用于建立起调基准，最终强弱仍以同版本试玩为准。交付不会修改现有战斗逻辑或资源数值。

## 1. 先这样使用

1. 打开同目录的 **数值调参工作簿.xlsx**，先看“调参总览”。
2. 黄色单元格可改。先调整“单位战力”里的生命、攻击、防御、费用，再看每费战力和反推生命。
3. 需要改变技能时，改“技能输出”的倍率、冷却、命中帧数、平均目标数和施法占用时间。
4. 到“波次压力”观察 5 份关卡前 12 轮的变化，再到“路线收支”检查一条路线能否保留合理生命。
5. 把确定要试的数值填回 Godot“游戏配置”或“波次编辑器”。Excel 不会自动改游戏。
6. 每次只改一组参数，用“试玩记录”记下版本、关卡、策略、随机种子、耗时和掉血，再决定下一步。

**推荐第一轮只处理：高生命单位、无效效果牌、空波次和节点战斗长度。** 金币和完整商店经济可以等消耗入口确定后再调。

| --- | --- | --- |

| 初始牌组 | 士兵 3、弓箭手 2、防御 2、力量强化 3，共 10 张 | 每轮抽 5，只有一半牌能直接提供部队 |
| 开局遗物 | 配置列 4 件，旧城防遗物被拒绝，实际 3 件有效 | 100 生命、十抽引擎、出征护甲是现有开局基线 |
| 开局药水 | 火焰、闪电、龙卷各 1 瓶 | 新手早期战力很受是否用药影响，分组测试 |
| 基础能量 | 第 r 轮为 min(3+r-1,10)，额外上限加在基础上限之后 | 不把 10 当所有能量的硬上限 |

| 回合扣血 | 胜者按 r + 幸存单位 hp_damage_value 之和扣败方玩家生命 | 战斗攻击力与结算扣血是两个独立维度 |
| 清场 | 每轮结算后双方单位全清，下一轮重新生成 | 普通单位强化不自动延续到下一轮的新单位 |
| 征召费用 | 原征召牌死亡或幸存清场进弃牌堆，都加 1 费；下一场重置 | 重复使用次数必须进入费用分析 |
| 牌堆 | 开打弃未用牌；抽空后洗弃牌；消耗牌本场不再抽回 | 不能用每轮独立随机抽 5 张代替全程牌序 |
| 敌方节点生命 | 当前 5 份关卡均为 45 | 打完波次数并不意味着节点胜利 |
| 非循环波次 | 列表耗尽后重用最后一个有效阵型，成长为 0 | 不把最后一波之后当作没有敌人 |
| 循环成长 | 仅指定范围循环；元数据的攻击/生命/防御按重复次数线性增加 | 不套指数成长到现有实现 |
| 本局成长 | 获牌、遗物、药水和永久强化 | 当前没有需要纳入模型的角色等级/经验系统 |

## 3. 分析分成五层

| 层级 | 主要问题 | 输出 | 对应工作表 |
| --- | --- | --- | --- |
| 单次命中 | 防御、闪避和技能倍率怎样改变伤害？ | 每击伤害、击杀命中数 | 技能输出 |
| 单位 | 单位能活多久，存活时能提供多少输出？ | 有效生命、DPS/HPS、相对战力 | 单位战力 |
| 部署 | 一点能量与一张手牌换多少作用？ | 每费战力、重复征召费用、效果估价 | 单位战力、效果与资源 |
| 节点 | 每轮敌阵是否过强，节点为何拖长？ | 波次压力、回合扣血、目标交锋数 | 波次压力 |
| 路线 | 前几场掉血会不会让后面的选择失效？ | 生命/金币/卡组收支、通关与耗时分布 | 路线收支、试玩记录 |

所有估算都有条件。战力指数不能直接翻译成胜率，压力 1.2 也不意味着敌人胜率 60%。

## 4. 基础战斗公式

记 A 为攻击、m 为技能倍率、F 为目标防御、H 为单位生命。

### 4.1 单次伤害：贴合现有代码

普通攻击的伤害：

    原始伤害 D_raw = floor(A × m)
    命中伤害 D_hit = max(D_raw - F, 1)
    期望伤害 E[D] = D_hit × (1 - p_effective)

当前资源使用非负攻击与倍率，所以 floor 与 GDScript int 的截断相同。

p_effective 只有在目标配置了 dodge_skill、伤害带有效攻击者、can_trigger_counter=true 时才等于 dodge_rate。**当前投射物命中传 false，不触发闪避反击；毒、爆炸、区域和药水走环境伤害，也不扣防御或判闪避。** 不给所有伤害统一乘 (1-闪避)。

环境伤害：

    D_effect = amount

多段攻击必须每段扣防御：

    总伤害 = 命中次数 × max(floor(A × m) - F, 1)

例如 15 攻、0.4 倍率、7 次命中，对 5 防：每段 max(6-5,1)=1，共 7。不能算成 15×0.4×7-5=37。

近战反击要额外考虑反击动画占用、打断原攻击和无法无限互相反击。工作簿“反击DPS”留作可填的实测值，初值 0。

### 4.2 击杀所需命中数

    命中数 N_hit = ceil(H / D_hit)

这里只算成功命中的次数。用 N_hit/(1-p_effective) 可以近似攻击尝试数；不能据此保证击杀时间，动画、走路、受击中断和集火都可能改变结果。

### 4.3 有效生命

工作簿采用统一参考来袭每击原伤 D_ref 和来袭近战占比 q：

    H_eff = H × D_ref / max(D_ref - F, 1) / (1 - p × q)

起调参考：D_ref=15，q=70%。这是比较条件，不是引擎新增规则。

士兵 100 生命、5 防、0 闪避，在这个参考下有效生命为 150。护甲加固 +3 防后为 100×15/7≈214.3，约增加 42.9%。如果敌人只有 9 点每击原伤，防御从 5 提到 8 会把伤害从 4 压到 1，收益是另一种量级。

因此，先确定常见每击伤害，再给防御定价。避免大量单位长期处于“每击只掉 1”的区间，这会拖长不限时交锋。混合来袭伤害很广时，改用各攻击伤害的加权平均，而不是只用一个 D_ref。

### 4.4 技能输出不能简单相加

引擎同一时间只释放一个主动技能，优先级高的先选。冷却从开始施法时计，动画结束或手动 finish 后才解除动作锁。

工作簿的长期近似按优先级依次计算：

    已用动画时间占比 B_i = Σ(先前技能频率 × 施法占用秒数)
    技能频率 f_i = min(可用目标比例 / 冷却, max(0,1-B_i) / 施法占用秒数)
    DPS_i = f_i × 每次命中数 × 平均命中目标数 × 每击有效伤害
    单位 DPS = ΣDPS_i × 输出在线率 + 实测反击DPS

治疗技能用实际治疗公式 floor(A×m)，不扣防御。可用目标比例用来折损满血、没有合格目标的情况。吸血还受过量治疗、击杀溢出和自身死亡限制，表内只给近似值。

施法占用秒数来自 SpriteFrames 各帧持续值之和/动画速度。冲刺另加距离/速度近似占用。手动结束技能优先用实测占用值替换。

此估算有三项重要局限：所有技能开场即可释放，短交锋爆发与长期频率不同；同优先级次序可能影响实际选技；高优先级技能目标不在范围内可能阻碍其他技能。最终用“实际伤害/存活秒数”校准输出在线率和施放次数。召唤技能本身不是伤害，不能把召唤倍率当DPS。

## 5. 单位战力与费用公式

把士兵当参考单位，规定其战力 P0=1。使用参考条件下的输出和有效生命：

    D_total = 有效DPS + w_heal × 有效HPS
    P_body = sqrt((H_eff/H_eff0) × (D_total/D_total0)) × 阵型系数
    P_unit = P_body + 召唤附加战力
    每费战力 = P_unit / 当前费用

w_heal 初值 0.5，仅是估价假设。阵型系数初值 1；输出在线率远程初值 1、近战初值 0.8，均需校准。输出在线率与阵型系数不要同时重复补偿同一种走位优势。

sqrt(H×DPS) 是用于预算与筛查的近似。它不描述克制、集火、前排保护、短战爆发和召唤滚雪球。牧师、死灵法师、范围伤害单位尤其需要组合实测。

### 5.1 按费用建立目标预算

    P_target(c) = c × [1 + b × (c-1)]

b 起调 0.08，则 1/2/3 费目标战力为 1 / 2.16 / 3.48。高费单位略有溢价，补偿一张手牌的限制和高费难以部署。它们仍需前排、后排和功能角色差异。

先让同费用常规单位的每费战力大致接近，再用约 ±15% 的预算换角色特色。工作簿 0.75～1.35 的宽诊断范围只用于发现明显异常，不是必须达到的终局平衡线。

### 5.2 反推生命

若攻击、防御、技能与费用保持不变，只调整生命：

    H_new = H_old × [(P_target-P_summon)/(P_current-P_summon)]²
    最后按 5 点生命取整

该公式依赖输出不随生命改变。吸血、治疗、召唤次数和存活时间明显联动时，需要重新试玩，不能直接照抄反推结果。工作簿有“反推生命”列，可以先产生候选值，再决定单位角色。

若想同时改攻与生命：先给单位确定前排/后排/刺客/辅助角色，确定攻击与技能，再反推生命。不要为了指数一致把所有单位改成同一个形状。

## 6. 征召牌重复使用、抽牌与效果牌

### 6.1 重复征召费用

    某张牌第 j 次部署费用 = 基础费用 + j - 1
    同张牌连续部署 k 次总费用 = k×基础费用 + k×(k-1)/2

初费1的士兵用4次分别为1、2、3、4费，共10。初费2的骑士用4次为2、3、4、5费，共14。加费仅本场，新节点重置。

由此可见，长战会持续挤压部队数量。敌方循环成长、征召加费、回合数扣血这三条压力同时上升，建议先把普通节点压到合理交锋数，再增强循环成长。

工作簿对第 r 轮平均征召费用用：

    c_avg(r) = c0 + (r-1) × 每牌每轮平均退场次数

这是牌序的近似，不代表所有征召牌每轮都会加费。默认0.35，需要用每张具体牌的实际使用记录校准。

### 6.2 初手稳定性

在不放回抽牌的条件下，牌组 N 张、某类关键牌 K 张、抽 d 张：

    P(抽不到关键牌) = C(N-K,d) / C(N,d)
    E[关键牌张数] = d × K/N

当前 N=10、d=5、征召K=5：缺征召概率1/252≈0.40%。前排只有3张士兵：缺前排概率21/252≈8.33%。

这是第一手概率。长战存在弃牌、上场牌暂不在可抽集合、消耗牌、加费和禁抽，不能直接套到每一轮。新增牌若不提高关键牌比例，会稀释稳定性。事件每次加一兵种一效果也应检查对现有构筑是否真的有用。

不放回抽样概率依据：[SciPy 超几何分布定义](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.hypergeom.html)。

### 6.3 效果统一按增量估价

    增量战力 ≈ P_target_unit × [sqrt((1+Δ有效生命/H_eff) × (1+Δ伤害/(DPS×观察秒数))) - 1]
    毛能量价值 = 增量战力/参考每能量战力 × 兑现率
                   + 附加单位/抽牌价值 + 净获得能量
                   - 玩家生命成本×生命能量估值
    净能量价值 = 毛能量价值 - 卡牌费用

这里的 target_unit 指被强化单位。工作簿先按参考士兵估价，Δ伤害、兑现率和附加战力均能调整。复制强单位、给高生命单位百分比治疗时，应改成真实目标重新计算。

| 效果 | 计算办法 | 当前实现中特别要看 |
| --- | --- | --- |
| 攻击强化 | 按每个技能重算伤害前后差×实际次数 | 平减防御存在取整和最低伤害阈值；表内比例法只是起调近似 |
| 防御强化 | 重算 H_eff 前后差 | +3防对小伤害敌人的价值可能远高于大伤害 |
| 生命强化 | 增加最大生命及实际回复，重算战力 | RUN绑定原征召牌才跨节点保存 |
| 单位治疗 | min(缺失生命,ceil(最大生命×百分比)) | 当前出牌仅准备阶段，单位一般满血，普通治疗卡通常无法兑现 |
| 中毒 | 附毒命中数×层数；在回合末结算 | 不影响交锋中的击杀DPS；主要减少胜方幸存者，可能将败轮变平局 |
| 死亡爆炸 | 每目标实际扣血，分别记录友军与敌军 | 当前实现遍历附近双方，不能照“只伤敌人”的旧文案估价 |
| 复制 | 被复制单位的实际增量战力和幸存扣血 | 当前继承强化，与卡牌旧说明不一致；没有原牌、不加牌堆数量 |
| 区域伤害 | 每跳伤害×有效跳数×平均目标×停留比例 | 地面区域可跨本场回合保留；重叠区域要计算叠加 |
| 泥潭 | 对实际出手机会、绕路和远程先手的改变 | 当前双方减速80%，不是直接伤害 |
| 抽牌 | 新增可用选项带来的有效部署与效果 | 抽到牌还得付费用，抽牌卡本身还占一张手牌 |
| 免费随机出牌 | 成功打出的牌实际价值，减随机目标/位置损失 | 当前可连锁，限制存在但仍需观察是否成为固定最优选择 |
| 生命换能量 | 净能量 - 消耗生命×估值 | 血契补给0费，花3玩家生命得3能量，可超过上限，可重复抽回 |
| 回撤 | 恢复的部署机会、规避加费与站位收益 | 当前回手牌，不是旧说明的弃牌堆；再次征召需支付费用 |
| 死亡光环 | Σ死亡事件后各单位额外输出 | 本场死亡累计影响后续新部队；清场退场不算死亡 |
| 增减时长 | 当前有效价值0 | 已被运行时拒绝，建议从奖励池排除 |

**特别区分三类持续：** 普通单位强化 BATTLE/ROUNDS 都随该单位退场消失，不自动写回原征召牌；RUN保存到原牌并在再次部署时恢复；区域 BATTLE/ROUNDS 按场或回合保留。不能把力量强化“2回合”直接乘两倍收益。

0费、抽牌、免费出牌和生命换能量要一起试，关注有没有“先抽循环牌就必须连续点很多次”的单调最优玩法。优化时优先考虑本场消耗、触发次数或效果上限等机制，但这份交付不改现有机制。

## 7. 敌阵、循环与节点战斗长度

### 7.1 敌阵压力

    敌阵战力 P_enemy(r) ≈ Σ各敌单位P × 阵型修正
    预计征召数 n(r) = min(可用能量×征召能量占比/c_avg(r), 抽牌数×征召牌比例)
    玩家部署预算 P_player(r) ≈ n(r) × 参考单位战力
    压力比 Q(r) = P_enemy(r) / P_player(r)

工作簿暂把站位修正放在单位表，并使用统一参考单位。它没有推演真实手牌选择或具体队伍克制；因此 Q 只用来找异常波次和后期成本压力。

首版设计假设：教学波压力0.7～0.9；普通波0.9～1.15；关键难波1.15～1.35。每隔2～3波留一个较低压力波。超过1.35的连续波次先检查，而不是一律砍怪。以上区间属于预算起点，不是由现有游戏实测得出的结论。

可以反推敌人数：

    敌人数 ≈ round(目标压力 × 玩家部署预算 / 单个敌单位战力)

先改敌人数和站位，其次改单位属性，最后才提高循环成长。不要同时增加人数、攻击、防御和敌方节点生命，之后很难定位体验变化来自哪里。

### 7.2 循环成长

现有实现：

    属性 X(c) = 基础属性 X0 + c × 每循环增量 g
    首次循环 c=1，不是原始波次 c=0

如 level_003 循环3～5波，6～8轮属于第1次重复、9～11轮第2次重复。配置的部分单位每循环攻击+2。工作簿按这个规则展开前12轮。

波次成长后的精确伤害应逐技能重算。工作簿为简化，把成长折算成有效生命与攻击差值比例，只做压力趋势估计，防御阈值附近或低倍率多段技能要回到技能表逐击检查。

### 7.3 节点生命反推

若第 r 轮玩家胜率为 p_r、平均幸存扣血和为 S_r，则不计平局：

    预计对敌节点伤害 = Σ p_r × (r+S_r)
    预计玩家损失生命 = Σ (1-p_r) × (r+敌方平均幸存扣血和)

若平局概率为 d_r，则后一项应为 (1-p_r-d_r)。工作簿路线示例为了简明暂设平局0。

给定目标 R 轮结束，可以倒推：

    敌方节点生命 ≈ Σ[r=1..R] p_r×(r+S_r)

例如 p=0.75、S=3、R=8，期望敌方伤害0.75×(36+24)=45，与当前45生命相符。但真实胜负和幸存人数相关，不能靠这个均值保证8轮结束。累计实际伤害首次达到 enemy_max_hp 才是节点完成。

起调体验目标：普通节点6～8次交锋、Boss8～10次。若每次交锋12秒、准备10秒，8轮约176秒再加结算与切场；先检查这样的一局总时长是否符合你的预期。不要用降低 battle_duration 来缩短交锋，它已不控制结束。

### 7.4 当前5份关卡的实际波次

| 关卡 | 原波次人数 | 规则 | 核查点 |
| --- | --- | --- | --- |
| level_001 | 2、2、3、0、4 | 非循环，之后重复末有效波 | 第4轮空波可无战斗输出结算压力 |
| level_001_1 | 2、2、3、0、4 | 非循环，之后重复末有效波 | 当前阵型数量与level_001相同 |
| level_002 | 5、5、0 | 1～3循环，无成长 | 空波每3轮重复，Boss节奏有固定喘息 |
| level_003 | 1、1、2、2、3 | 3～5循环，部分单位攻击+2/循环 | 同时面对征召涨费和敌人成长 |
| level_template | 5、5、5 | 非循环，之后重用末有效波 | 模板名字“双兽人”与真实5哥布林不一致 |

## 8. 玩家生命、奖励与经济

### 8.1 路线生命

    HP_next = clamp(HP_now - 节点实际损失 - 事件付血 + 有效回复,0,HP_max)
    有效回复 = min(回复数值,当时缺失生命)

玩家已经死亡不能被后续休息节点救活。工作簿示例按这个规则阻断后面的治疗。

建议起调：普通节点预期损失约6～10实际生命，难节点10～16，Boss15～30。是否需要调整取决于路线中战斗数量与治疗机会。用当前100实际开局生命，不把它当成5～10场每场都能输掉20血的预算。

第一幕目标可先设为：普通路径进入Boss时仍有40～65生命，通关后剩15～40。还要记录P10低位剩余生命和失败节点，而不只看平均值，防止开局运气差就无法翻盘。

玩家生命换能量的估值建议这样校准：

    每点生命的能量价值 λ_HP ≈ 增加能量能少掉的玩家生命的倒数

表内0.25能量/生命仅用于开始比较。若3点额外能量能少掉8生命，花3生命获得它就很划算；若不能改变胜负或幸存扣血，就可能白付3血。

### 8.2 奖励要能改善接下来的决策

普通节点完成可以规划“奖励选择 + 少量金币”，关键节点给遗物或药水，但当前战斗完成逻辑没有完整统一的战后奖励闭环。不要把规划奖励当成已实现收入。

设计起点：每2～3个战斗/事件有一次有用的构筑选择；不强制把所有奖励牌塞入牌组。已有招募事件从5张兵种和5张效果牌各选1张，长期会同时增加关键牌和辅助牌，需要检查是否稀释初手。

遗物同ID不重复获得；旧城防遗物无法获得。随机遗物事件要按“尚未拥有的可用池”评估，不能把重复遗物算成另一份收益。

### 8.3 遗物和药水

抽牌能量遗物：

    本次获得能量 = [floor((已有余数+实际抽牌数)/阈值)]×amount
    新余数 = (已有余数+实际抽牌数) mod 阈值

计数跨回合、跨战斗保留。十抽引擎+行军戒指各自计数，不共享余数。随机直接出牌和回撤不算抽牌。波次表为简化只按十抽引擎、每轮实际抽满5张、初余数0计算，无法代表禁抽或不足牌时的真实能量。

出征护甲只在本场首次自动交锋给当时的己方单位加防。该队伍清场后，新单位不会再自动吃到护甲。不能按“每场前3轮全队永久+2防”估价。

药水不占手牌、不耗能量，但一瓶效果结束后才用下一瓶。价值以改变交锋胜负和减少玩家掉血为主：

    总有效伤害 ≈ 每跳伤害 × 命中跳数 × 平均命中目标数 × 覆盖率

火焰落地先命中一次，之后每0.5秒6伤害直到本轮结束；龙卷落地先命中，之后6秒内每0.5秒8伤害，临近结束的跳数受帧时序影响；闪电4次各20伤害，需实际点完。范围伤害忽略防御与闪避，针对高防单位的优势要实测。

表内折算能量只是与“士兵观察时间内输出”的比较，不能代替瓶数定价。

### 8.4 金币先做收支预算

    Gold_next = max(0,Gold_now + 真实收入 - 实际花费)
    可购买次数 ≈ 可支配金币 / 目标平均价格

当前基础开局99金币，遗留事件有+15金币，但没有完整商店消耗闭环。路线表因此默认新战斗奖励/支出都是0，供你将来定义后填写。

未来引入商店时再考虑价格起点：普通卡40～60、药水25～40、移除牌50～80、遗物100～150。**这些是未来功能的候选预算，当前没有接入，也不建议只加收入而没有消耗。** 先定一幕希望购买几次，再从实际收入反推价格，而不是凭感觉让金币持续堆积。

## 9. 试玩记录与调参方法

先固定3套测试策略：前排+弓手、强化一个核心单位、召唤/免费出牌组合。药水使用与不使用分开，站位至少测试集中和分散两种。同版本、相同种子和相同策略做改动前后配对比较，避免只凭一次输赢。

初筛每种主要组合10～20场，找方向；接近目标后每个主要关卡累计30～50场再判断。独立玩家试玩与开发者自己反复玩的表现要分开，数字是建议采样工作量，不代表统计上已经足够。

| 指标 | 定义 | 异常时优先改 |
| --- | --- | --- |
| 交锋胜率 | 赢的交锋/全部交锋，平局另计 | 敌人数、站位、单位克制；不要先调节点生命 |
| 遭遇胜率 | 胜利节点/完整试玩节点 | 前期压力、成长、补给和敌节点生命 |
| 首轮空转率 | 未能进行有意义部署的首轮比例 | 关键牌比例、费用、抽牌；停用牌奖励池 |
| 能量利用率 | 实际消耗能量/实际得到能量 | 征召涨费、费用分布、缺目标牌 |
| 单位生存/输出 | 实际伤害与治疗/存活秒数 | 生命、防御、动画、命中帧、输出在线率 |
| 战斗长度 | 准备+交锋+结算的中位数与P90 | 坦度、每击伤害阈值、敌节点生命 |
| 波次损失 | 每轮玩家掉血与幸存敌单位扣血 | hp_damage_value与回合数，不拿攻击力代替 |
| 牌选择率/使用率 | 同样可选、同样可用条件下的采用比例 | 费用和兑现条件；强弱结论需排除牌组偏差 |
| 路线掉血 | 每节点实际损失、Boss进入生命、失败位置 | 回复机会、节点数量、付血事件 |
| 构筑多样性 | 不同策略的成功率与决策步骤 | 免费出牌、复制、召唤是否固定最优 |

单位长期输出低，先看有没有打不到或动画占用，再调攻击。时间过长，先看是否大量伤害落在1点，再调生命。遇到无效治疗和停用时长牌，先处理可用性与奖励池，单纯降费用解决不了。

胜率用95% Wilson区间辅助判断，p=w/n：

    中心 = (p + z²/(2n)) / (1 + z²/n)
    半宽 = z × sqrt(p(1-p)/n + z²/(4n²)) / (1+z²/n)
    下限/上限 = 中心 ∓ 半宽，z=1.96

工作簿已有公式，未记录场次时保持空白。10胜/20场的区间约29.9%～70.1%，不能据此断言“稳定50%”。同玩家、同种子的重复场次不独立时区间会过于乐观。

统计依据：[NIST Wilson比例置信区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。

## 11. 框架的适用边界

工作簿保留当前配置快照，黄色模型输入的变化不会回写游戏，修改游戏资源后也不会自动刷新本工作簿。支持脚本可重新导出和重建，但重建会覆盖Excel中的手动调参，因此先另存你的调参版本。

已经核验资源读取、生成工具中的公式重算、代表性输入变动、7张工作表版面，以及保存后的1087条公式、原始单位参数和图表。未在Microsoft Excel客户端直接测试重算；常规Excel公式及缓存检查通过。

未把公式当成真实自动战斗模拟器，也未进行成套策略的胜率试玩。召唤、反击、地形、免费出牌连锁、药水目标与卡序需要实际运行校准。

不要追求所有单位同一胜率。先让每个单位有明确用途，让一次失误仍有恢复空间，让路线中的资源选择会影响之后的部署；然后用这套公式定位过强、无效和拖长的部分。
