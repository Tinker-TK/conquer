# 四层地形与桥梁

正式战场的 `Level/NavigationRegion2D` 已接入四层系统：`Layer01`、`Layer02`、`Layer03`、`Layer04` 分别对应逻辑楼层 1、2、3、4。继承关卡的原有瓦片数据保留。

## 编辑器烘焙与运行时导航

这套战场**不需要点击 NavigationRegion2D 原生的“烘焙导航”按钮**。进入战场后会分别生成四张导航地图；编辑器手动烘焙出来的多边形会被运行时结果替换。原生按钮不会按本系统的逻辑楼层分别处理，多个高度的地形一起解析时，显示的网格可能与实际四层路径差异很大。

编辑地形后保存并重新运行。运行时可在远程场景树中查看第一层的 `NavigationRegion2D` 和第二～四层生成的 `Floor02Navigation`～`Floor04Navigation`；单位使用与自身 Floor Id 对应的地图。单位避让会让实际移动稍微偏离路径线，但仍受该层可走区域和物理碰撞限制。

## 画地形

在对应 Layer 上正常绘制瓦片。瓦片中已有的碰撞多边形只阻挡同层单位；桥面中间保持可走，在栏杆、边缘等位置绘制碰撞。桥墩要阻挡桥下单位时，把桥墩碰撞放在 Layer01，或放在原有 `Collision` 容器中。

开场时系统会复制各层 TileSet，按该层瓦片的实际范围和碰撞分别烘焙导航。上层障碍不会从下层导航中挖洞；空的上层没有可走区域。编辑器原来的“烘焙导航”不再决定运行时的四层路径。

`stair02`、`stair03`、`stair04` 默认分别归入第 2、3、4 层，主 `Layer01`～`Layer04` 下的子 TileMapLayer 也会归入相应楼层。导航、地形碰撞和绘制顺序会一起配置，不增加逻辑楼层。其它同层的附属瓦片层可在 NavigationRegion2D 的 `Floor 1 Extra Layers`～`Floor 4 Extra Layers` 中填写相对节点路径；装饰瓦片请放在这些地形层之外。

合并图块按实际图像尺寸、Texture Origin、翻转和节点变换计算可走范围，避免大瓦片只算一个格子。对于有透明三角的斜坡或岩壁立面，可以在 TileSet 中给该瓦片配置 Navigation Polygon，明确指定真正可走的地面；它会优先于默认矩形范围。

现有方形瓦片、缩放和变换会计入导航。地形在进入战场时生成一次；在编辑器中修改地图后重新运行即可，不支持运行中实时改瓦片后自动重烘焙。

## 单位在哪一层

单位检查器新增 **Floor Id**，默认为 1。敌方波次中也可直接配置该值。脚本可调用 `unit.set_floor(2)`。

切层会同步更新：地形碰撞、同层单位身体碰撞、导航地图、避让分组、显示顺序。阵营标记继续保留，策反等原有逻辑仍然有效。

征召可放在所有楼层真实可走导航的左半边，左右分界线按全部楼层的整体范围计算。落点自动决定单位的 Floor Id；多个楼层重叠时优先部署到最上方可走楼层，并同步设置碰撞、导航和绘制顺序。**Deployment Floor** 仅供没有四层系统的旧单层场景兼容。复制品继承被复制单位的楼层，技能召唤物继承施法时的楼层。

## 飞行单位

大黄蜂（`bumblebee`）、小恶魔（`imp`）、巨型蝙蝠（`giant_bat`）和蝙蝠（`bat`）的单位资源已启用 **Is Flying**；Godot 游戏配置表显示为「飞行单位」。其它单位默认关闭。

飞行单位直接向目标移动，不计算导航路线、不绕墙或寻找楼梯，可以飞越水面、实体障碍、导航缺口和断开的岛屿。索敌仍遵循各自技能的最近／最低血量等规则，最近敌人的距离按直线计算；没有可用楼梯的远处高层敌人也能被追击。飞行单位不阻挡地面身体，阵营查询与受击仍然有效。

跨入高层时向上快速移动 **64 像素**，跨入低层时向下快速移动 **64 像素**；每层固定 **0.1 秒**，连续层差逐层完成。升降带动整个单位，因此精灵、血条、受击与攻击位置保持一致。升降期间先完成动作再攻击；下降时在整个身体离开岩壁前保留较高绘制层，避免被岩壁遮住。

地形判层直接读取原始瓦片地面轮廓，不使用烘焙导航的 24 像素留白；各层按每层 64 像素的投影还原到同一移动平面，避免爬升后又被原边界判回低层。无瓦片的空域按第一层处理。明确指定目标楼层时可以到达重叠地形的下层落点；准备移动和落点提示均保留飞行目标原坐标，不吸附到导航边缘。眩晕、死亡和切阶段会停止当前飞行；暂停与战斗倍速共用物理时钟。

运行 `python tools/maintenance/run_checks.py --checks flying` 验证四种正式单位的无导航飞行、墙和水面、三层上升／下降、逐次 64 像素与 0.1 秒、眩晕恢复、死亡、索敌、真实攻击，以及正式第 5 关关闭所有楼梯后的往返。图形验收使用共用测试入口的 `--flying-preview`，将四种单位在正式地图升降时的 24 张画面保存到 `.maintenance/checks/flying-visual/`，并与强制前景逐像素比较，检查岩壁遮挡和暂停冻结。

## 跨层攻击与高地增伤

狼人扑击、骑兵冲锋、熊人跳砸和剑士后撤/前突已支持楼梯上的主动位移：在坡口附近通过已配置的有效连接完成切层，抵达后继续技能；墙体、地表边界、单向和禁用楼梯仍有效。位移过程同步导航、碰撞、避让及坡道显示顺序，详见 [楼梯位移攻击](楼梯位移攻击.md)。

近战、远程和攻击技能均可跨层命中，施放距离仍按世界坐标中的技能射程判断，不额外增加楼层距离。在射程内时单位停步攻击，无需楼梯连接；超出射程时地面单位按楼梯路线接近，没有可达路线的远处敌人不会被地面单位当作可追击目标，飞行单位直接飞近。地面身体碰撞和避让继续按楼层隔离。反击也必须在其技能射程内。

高层攻击低层时，每高一层增加 **10% 最终攻击伤害**，按层差线性相加：

| 攻击层 → 目标层 | 伤害倍率 |
| --- | --- |
| 2 → 1 | 1.1 倍 |
| 3 → 1 | 1.2 倍 |
| 4 → 1 | 1.3 倍 |
| 同层、低层 → 高层 | 1 倍 |

先结算原有距离效果、防御和易伤，再应用一次高地倍率，结果四舍五入到整数；不修改单位攻击属性。双方阵营均适用，友军仍不能互相伤害。毒、环境直接扣血和治疗沿用原有数值，不享受攻击增伤。

直接命中按命中时双方楼层计算；投射物保存发射时楼层，攻击者之后切层或退场不改变已发出的箭矢，目标按受击时楼层计算。穿透弹对每个目标分别计算层差。

## 放楼梯或坡道连接点

1. 把 `scenes/world/foolrtransition/floor_transition.tscn` 拖入 `Level/NavigationRegion2D/FloorTransitions`。
2. 在检查器设置 **From Floor** 和 **To Floor**，例如 1 → 2。**Bidirectional** 控制是否允许返回，**Enabled** 控制连接是否开放。
3. 调整其 `From`、`To` 两个 Marker2D，分别放到对应楼层的可走区域内，避开栏杆、墙和导航边缘的留白。
4. 连续楼梯建议让两个标记重合在上下层可走面的交叠处，单位走到连接点就原地切层。需要投影位置偏移的楼梯/入口可以分开放置：到达入口后会将单位放到出口，不会播放额外的上下楼动画。

导航留白由 NavigationRegion2D 上的 **Floor Agent Radius** 控制，默认 24 像素。标记必须位于烘焙后可走区域内；入口或出口无效的连接不参与寻路，出口被同层单位堵住时等待。多段楼梯可串联，AI 会规划经过 1 → 2 → 3 → 4 的路线。

不要只根据图片边线放标记：24 像素的留白意味着贴着瓦片边缘的点可能位于导航外。`battle_005` 的三处连接已调整到两层都可站立的位置。Area2D 的缩放/碰撞形状不会改变逻辑切层的连接点范围，当前路线仍走 From/To 标记点。

楼梯的 `CollisionShape2D` 范围用于坡道上的绘制排序，形状应覆盖实际画出的台阶，可独立调整它相对连接点的位置。只有正在沿该楼梯行走的单位，可见身体与这个范围接触后就临时按较高层绘制；整个身体离开后才恢复实际楼层的绘制顺序。不能等脚底进入才抬高，否则头部和武器会先被岩壁盖住。可见范围从动画图片的非透明部分计算，并合并整段动画，避免不同走路帧的宽度变化造成遮挡闪烁。导航、碰撞和技能判定仍使用实际楼层，直到抵达 From/To 才切层。桥下普通经过不会触发抬高绘制。移动避障的前探距离也会截断在当前目的地，避免把楼梯连接点之后的本层导航边缘误当成墙，导致先停步或侧绕再上下楼。

自动战斗会按目标单位的真实楼层寻路。准备阶段右键优先保留当前层；落点仅在其它层可走时选择该层，随后经过楼梯前往。重叠位置使用 **Alt + 右键** 指定该落点最近的上层，使用 **Ctrl + 右键** 指定最近的下层。仍然需要存在可达楼梯，不能直接跳上桥。移动落点提示也使用同一目标楼层。脚本可以用 `unit.navigation_agent_2d.move_to(world_point, target_floor)` 明确指定目标层。

经过楼梯在其它楼层的 XY 投影不会触发切层。此场景的 Area2D 不使用 `body_entered` 自动交换楼层，切换由实际规划的楼梯路线驱动，避免桥下经过时误上桥。

## 保留的物理位

| 物理层 | 用途 |
| --- | --- |
| 1、2 | 原有 team_a / team_b 阵营查询 |
| 3 | 原有 entity，共用实体障碍 |
| 4～7 | Layer01～Layer04 地形 |
| 8～11 | Layer01～Layer04 单位身体 |

TileSet 的楼层碰撞位由系统在运行时配置，不要把不同楼层的单位身体重新配置为按阵营位互相阻挡。原 `Collision` 容器里的 land 障碍属于第一层；entity 障碍保留跨层阻挡行为。

## 验证

`battle_007` 的四座同层桥保持第二层通行：两处竖桥覆盖的岩壁格使用关卡独立碰撞变体开口；桥柱变体分别保留横桥72像素、竖桥80像素通行带，外侧护栏保持碰撞。导航仍使用24像素留白，避免48像素的桥柱净宽被两侧留白完全挤掉。仅修改地形外观、保留桥柱或桥下整格岩壁碰撞时，导航仍会断开，索敌会排除这些不可达目标。

本场景四处外侧坡道分别配置一层和二层的有效 From/To 标记；实例缩放会同时缩放标记偏移。`tests/fixtures/battle_007_movement.json` 保存全部四处坡道双向、四座桥双向及连续跨桥的真实移动案例。`python tools/maintenance/run_checks.py --checks level108-navigation wave-spawn-floors` 另行使用 `level_108_1` 第2回合，验证士兵、骑士与六只敌人的自动索敌、实际移动和双方动画命中。

这四处坡道使用关卡独立的 `scenes/levels/battles/battle_007_floor_transition.tscn` 保存 From/To 端点，主场景只保存实例位置和缩放；右侧实例沿 X 镜像。避免仅依赖主场景中嵌套 Marker 的临时覆盖值，重新保存后又把一层入口恢复到二层位置。`--checks level108-cross-floor` 进一步验证保存重载、士兵四处坡道双向通行及第5回合四只一层怪实际上楼命中。

四层回归使用真实瓦片碰撞、单位导航与自动战斗，覆盖桥下通行、同层阻挡、跨三段楼梯、反向/关闭连接、出口占用、死亡释放，以及跨层近战、远程索敌和实际动画命中、逐层增伤、发射后来源退场及穿透逐目标结算。战术牌回归另行验证距离/防御/易伤叠加，反击回归验证跨层防守反击。

```powershell
python tools/maintenance/run_checks.py --checks floors targeting targeting-navigation counter tactical-cards sword-arrow skeleton-archer wizard-fire-ball
```
