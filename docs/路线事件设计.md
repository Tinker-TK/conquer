# 路线事件设计：让每一次绕路都值得犹豫

> 版本：v0.1｜日期：2026-10-18｜适用范围：第一章「翠绿原野」，结构可复用到后续章节
>
> 目标：不增加战斗数量的前提下，用一组有代价、有取舍、能改变本局构筑的路线事件，做出接近《杀戮尖塔》的肉鸽体验。

---

## 0. 先看结论

- **现在不是事件数量不够，而是事件没有代价。** 当前 3 个常规奇遇（不含篝火）基本是「拿奖励 / 离开」，事件点越多，路线越轻松，玩家不需要为选择付出任何东西。
- **首批做 8 个事件即可明显改善体验。** 只需要给选项加「生命 / 金币 / 最大生命」成本，再扩展现有选牌模板、补一个删牌效果，不必重写整个事件系统。
- **20 个事件分两批落地。** 首批 8 个只依赖「成本、单组三选一、删牌、最大生命」；其余 12 个等复制、随机强化、赌局、复合效果就绪后再上。旗标、连锁和战斗事件留给后续章节。
- **事件点要变成「未知」。** 地图上不直接显示事件标题，进入后再揭晓；同一局不重复，按楼层和稀有度抽池。
- **事件收益要和一场普通战斗大致相当。** 普通战斗是 30 金币 + 三选一卡牌 + 25% 药水；事件不能稳定给出两倍于它的免费收益。

### 建议的落地顺序

| 阶段 | 做什么 | 产出 |
| --- | --- | --- |
| 第 1 步 | 选项成本、单组三选一、删牌、最大生命变化 | 8 个可玩事件 |
| 第 2 步 | 复制、随机强化、赌局、复合效果、事件池与不重复 | 其余 12 个事件 |
| 第 3 步 | 旗标/连锁、战斗事件、后续章节池 | 后续章节扩展 |

## 1. 现状诊断

### 1.1 当前路线的真实数据

按 `data/levels/第一章 ·  翠绿原野.json` 统计：

| 项目 | 数值 |
| --- | --- |
| 地图节点总数 | 27 |
| 事件节点（type=1） | 11 |
| 篝火节点（type=2） | 4 |
| 战斗节点（type=0） | 9 |
| Boss / 商店 / 宝箱 | 1 / 1 / 1 |
| 完整路线数 | 16 |
| 单条路线事件数 | 2–5 个 |
| 单条路线普通战斗数 | 2–4 场 |

事件重复情况：

| 事件 | 出现次数 |
| --- | --- |
| 岔路的援军 | 6 |
| 篝火 | 4 |
| 旅人的药剂 | 3 |
| 遗忘的圣匣 | 2 |

也就是说，一条路线最多会经过 **5 个事件点，却只打 2 场普通战斗**。在现有「事件只给奖励」的规则下，这必然让事件路线比战斗路线更轻松。

### 1.2 为什么现在不像《杀戮尖塔》

| 现状 | 结果 |
| --- | --- |
| 选项大多是「拿奖励 / 离开」 | 没有真正的取舍，离开永远是最差选项 |
| 事件收益固定且偏大 | 事件点变成免费补给，路线风险失衡 |
| 事件标题直接显示在地图上 | 没有未知感，玩家在进节点前就知道会拿什么 |
| 同一事件反复出现 | 重玩时没有新故事，也没有新决策 |
| 事件很少碰牌组结构 | 不能删牌、复制、转化，事件无法改变本局构筑 |
| 没有代价，也没有失败 | 玩家的生命、金币、最大生命在事件里几乎不重要 |

### 1.3 现有系统里值得保留的部分

- 事件面板的「左插画、右叙事、横条选项」已经很适合短事件。
- 候选在打开时固定、领取只结算一次、查看地图/牌组不重抽，这些保护逻辑要保留。
- 篝火的「休憩 / 训练 / 强化」三选一已经是一个合格的事件模板，说明玩家能理解「只能选一项」。
- 五选一卡牌的界面可以复用为「三选一」或「单组选牌」。

**不要先做的东西：** 诅咒牌、强制战斗事件、复杂多阶段剧情。它们会显著增加系统和 UI 成本，但不会比「有代价的选项」更快带来肉鸽感。

## 2. 设计目标与原则

### 2.1 一句话目标

> 每次进入事件，玩家都应该问自己：**我现在缺的是生命、金币、牌组质量，还是未来的上限？**

### 2.2 七条原则

1. **每个事件只问一个问题。** 例如「用最大生命换一件遗物」「用一张废牌换一次强化」「用当前生命换金币」。不要在一个事件里同时问三个问题。
2. **代价必须可见。** 选项按钮上直接显示「最大生命 -8」「支付 35 金币」「失去 12 生命」，不能等点了才知道。
3. **每个选项都要有适用场景。** 如果某个选项在 95% 的局里都不会被选，它就不是选项，是装饰。
4. **事件要改变牌组或军队。** 纯金币事件可以有，但不能占多数；删牌、复制、训练、招募才是肉鸽感的核心。
5. **随机必须可承受。** 赌局要提前显示概率；失败不能直接结束本局；最好有保底收益。
6. **稀有度控制强度。** 直接给遗物、复制卡牌、双强化只能出现在后期或稀有池。
7. **文案短、具体、有画面。** 2–3 句话，先给场景，再给冲突，不要写设定集。

### 2.3 事件的三拍结构

```text
场景（你在哪里，看见什么）
  ↓
诱惑/代价（一个具体的交换，或一个未知的结果）
  ↓
选择（稳妥 / 进取 / 离开）
```

例子：

```text
场景：旧军团的旗手跪在路边，断旗拖在泥里。
诱惑：他愿意把旗交给你，但接过旗的人要背负旧军团的重量。
选择：接旗（最大生命 -8，得精锐征召牌）/ 取徽记（得金币）/ 立碑（回血 + 药水）/ 离开。
```

### 2.4 好事件的检验清单

- [ ] 三个选项里，至少有两个在不同构筑下都可能是对的。
- [ ] 选项的代价和收益能在一行内说清。
- [ ] 事件至少碰一个系统：生命、金币、牌组、兵种、遗物、药水。
- [ ] 失败/代价不会让玩家直接卡死。
- [ ] 文案里没有解释规则，规则都在选项上。
- [ ] 同一局不会重复遇到。
- [ ] 事件结束后，玩家能说出自己刚才换到了什么。

## 3. 事件模板与价值预算

### 3.1 六种事件模板

| 模板 | 玩家要回答的问题 | 典型选项 | 例子 |
| --- | --- | --- | --- |
| 交易 | 我愿意用什么换力量？ | 生命 / 金币 / 最大生命 → 遗物、卡牌、强化 | 镀金神像、血契 |
| 手术 | 我要不要把牌组变薄/变厚？ | 删牌、复制、强化、随机强化 | 铁匠的最后一炉、沉默的祭坛 |
| 招募 | 我要不要为某个兵种投入？ | 三选一征召牌、固定精英兵 | 折断的军旗、兽穴 |
| 赌局 | 我愿意承担多大波动？ | 押金币、押生命、概率遗物 | 骰子赌局、泥沼之手 |
| 叙事 | 我想成为什么样的队伍？ | 利他 / 贪婪 / 中立 | 难民队伍、被俘的骑士 |
| 地标/连锁 | 这次选择以后会不会回来？ | 设置旗标、后续回访 | 第二阶段再做 |

首批事件以 **交易、手术、招募** 为主，因为这三类最直接地改变本局强度，也最容易验证。

### 3.2 价值锚点

按当前配置：

| 参照物 | 当前值 | 设计含义 |
| --- | --- | --- |
| 开局 | 80 最大生命、99 金币、12 张起始牌 | 事件成本要按这个基数设计 |
| 普通战斗 | 30 金币 + 卡牌三选一 + 25% 药水 | 一场战斗的基准收益 |
| Boss 奖励 | 100 金币 | 后期事件不能超过这个量级 |
| 篝火 | 回复 30% 最大生命（80 血时 24 点） | 事件治疗不应全面替代篝火 |
| 商店卡牌 | 55–120 金币 | 事件送牌的价值参照 |
| 商店遗物 | 145–220 金币 | 直接给遗物必须有代价 |
| 商店药水 | 45–80 金币 | 事件药水奖励的参照 |
| 商店删牌 | 首次 75 金币，之后每次 +25 | 事件删牌不能明显更便宜 |
| 一次强化 / 训练 | 约 40–60 金币的等效价值 | 事件强化的参照 |

> 这些换算是设计比较用的，不是游戏内的硬兑换率。生命和最大生命不要直接用金币线性换算。

### 3.3 四档事件预算

| 档位 | 典型付出 | 典型回报 | 投放建议 |
| --- | --- | --- | --- |
| 小 | 无 / ≤25 金币 / ≤6 生命 | 30–50 金币、回复 12–18、1 瓶药水 | 早期常见，允许少量免费 |
| 中 | 30–60 金币 / 6–10 生命 | 1 张牌、1 次强化/训练、1 次删牌、60–80 金币 | 中期主力 |
| 大 | 8–12 最大生命 / 12–18 生命 / 70–100 金币 | 1 件遗物、2 张牌、复制 1 张牌、2 次强化 | 后期/稀有，每局最多 1–2 次 |
| 赌 | 30–60 金币 / 10–15 生命 | 50% 翻倍 / 50% 遗物，失败有保底 | 稀有，提前显示概率 |

三条硬规则：

1. **直接给遗物的事件必须有代价。** 最大生命、高额金币、或一场明确的冒险，三选一。
2. **免费选项只给小档。** 免费回血、少量金币、药水可以；免费送牌、免费遗物、免费删牌不行。
3. **任何代价都不能直接杀死玩家。** 生命成本至少留 1 点；最大生命成本后至少留 10 点；金币不足时选项禁用而不是变成 0 金币。

### 3.4 事件的「强度天花板」

单个**普通事件**的总收益，建议不超过 **1.5 场普通战斗**：

- 普通战斗：30 金币 + 1 张牌（约 60–90 金币价值）+ 25% 药水。
- 所以一个中等事件的总价值大约在 **90–120 金币等效**。
- **遗物事件是例外**：上限约 1 件遗物（180–220 金币等效），但必须让玩家付出 8–12 最大生命，或承担 15 点以上的当前生命风险。
- 事件路线可以比战斗路线多拿资源，但不能多到「闭着眼睛选事件」。

## 4. 路线投放

### 4.1 当前路线的问题

| 楼层 | 当前内容 | 问题 | 建议 |
| --- | --- | --- | --- |
| 1 | 1 个事件 | 开局第一个节点就是免费事件，缺少教学 | 固定为教学事件「岔路的援军」，只给 1 张牌 |
| 2 | 3 场战斗 | 合理 | 保留 |
| 3 | 4 个事件 | 事件密度最高的一层，容易变成连续读文本 | 压到 2–3 个事件，至少留 1 个战斗或商店 |
| 4 | 事件 + 篝火 + 战斗 | 合理 | 保留 |
| 5 | 2 个事件 + 1 场战斗 | 事件偏多 | 保留 1–2 个事件，补 1 个战斗/商店 |
| 6 | 事件 + 篝火 + 宝箱 | 合理 | 保留 |
| 7 | 事件 + 2 场战斗 + 商店 | 合理 | 保留 |
| 8 | 事件 + 2 场战斗 | 合理 | 保留 |
| 9 | 2 个篝火 | 其中一个标题写成「战斗」，类型却是篝火 | 先改标题，避免玩家误判 |
| 10 | Boss | 合理 | 保留 |

**目标结构：** 每条完整路线 **3–4 个事件点、3 场以上普通战斗、1–2 次篝火**。事件不再替代战斗，而是和战斗、商店形成三种不同的路线价值。

### 4.2 事件点要变成「未知」

现在的节点标题直接写着「遗忘的圣匣」「旅人的药剂」，玩家在进入前就知道结果范围。建议：

1. 地图上所有随机事件节点统一显示 **「旅途奇遇」** 或 **「?」**。
2. 进入后再显示事件标题、插画和正文。
3. 完成节点后，可以在本局路线日志里记录实际事件名；地图节点本身不必改回标题。
4. 商店、篝火、宝箱仍然显示明确图标，让玩家能规划路线；只有「奇遇」是未知的。

这一步对肉鸽感的提升，通常比再加 10 个事件更明显。

### 4.3 随机事件池

建议新增 `data/events/pools/act1.json`：

```json
{
  "id": "act1",
  "draw_without_replacement": true,
  "entries": [
    {"event": "golden_idol", "weight": 10, "min_floor": 3, "max_floor": 7},
    {"event": "last_forge", "weight": 4, "min_floor": 4, "max_floor": 8},
    {"event": "blood_pact", "weight": 4, "min_floor": 6, "max_floor": 9}
  ]
}
```

抽取规则：

- **事件元数据**：事件资源需要补充 `min_floor` / `max_floor` / `rarity` / `tags` / `requires` 字段；它们不显示在事件面板里，只参与抽池和同类上限。
- **不放回抽取**：同一局不会遇到同一个事件。
- **按楼层过滤**：`min_floor` / `max_floor` 决定事件是否可出现。
- **按稀有度加权**：普通 10、稀有 4、赌局 3、故事 2。
- **条件过滤**：队伍里没有可训练的兵种时，不抽「退役教官」；没有可删的牌时，不抽「沉默的祭坛」。
- **同类上限**：每局最多 1 个直接给遗物的事件、1 个复制事件、2 个删牌事件；事件资源带 `tags`（如 `relic` / `remove` / `duplicate` / `gamble`），抽池和统计都用同一套标签。
- **空池回退**：没有可抽事件时，使用「遗弃兵营」这类保底事件（25 金币 + 小治疗），不能让节点打不开。
- **首事件固定**：第 1 层固定为教学事件，不参与随机；后续事件才进池。

### 4.4 事件池的节奏

| 阶段 | 楼层 | 池子 | 目的 |
| --- | --- | --- | --- |
| 教学 | 1 | 固定「岔路的援军」 | 教会玩家「事件要选牌」 |
| 早期 | 2–4 | T1 普通为主 | 小交易、小风险，建立「事件有代价」的预期 |
| 中期 | 4–7 | T1 + T2 | 开始出现删牌、训练、复制、赌局 |
| 后期 | 6–9 | T2 + T3 | 遗物、双强化、高额赌局，为 Boss 前做最后决策 |

### 5.2 兵员与训练

#### 01 · 折断的军旗

**定位：** T2 / 稀有 / 第 3–8 层 / 队伍里至少 2 张征召牌

**正文：**

> 旧军团的最后一名旗手跪在路边，旗杆从中间折断，褪色的狮鹫旗面拖在泥里。
>

- **买下坑底的失败者**｜支付 40 金币｜从 3 张征召牌中选 1 张。

**设计意图：** 一个事件同时提供「生命换遗物」「金币赌局」「金币换兵」三条路，适合 Boss 前补强。

**实现：** `cost.hp` + `random_relic`；`gamble`；`cost.gold` + `choose_cards`（unit 3 选 1）。

> 如果以后事件系统支持真正启动战斗，可把「下场角斗」替换成一场精英战；首版用生命成本抽象，不在事件里嵌套战斗。

## 6. 现有事件怎么改

### 6.1 岔路的援军

| 项目 | 现状 | 建议 |
| --- | --- | --- |
| 奖励 | 五张兵种 + 五张战术，各选 1，共 2 张 | 改成单组三选一，只给 1 张 |
| 费用 | 免费 | 保持免费，作为第 1 层教学 |
| 频率 | 地图里出现 6 次 | 只固定在开局，后续由事件池抽取 |

推荐选项：

- **挑选一名新兵**｜从 3 张征召牌中选 1 张。
- **抄录一份战术**｜从 3 张战术牌中选 1 张。
- **只要一碗水**｜回复 12 生命。

理由：开局送 2 张牌会让玩家在第一次战斗前就获得过大的牌组优势，也让后续战斗奖励的「三选一」显得廉价。1 张牌足够建立「事件要选牌」的心智。

### 6.2 遗忘的圣匣

| 项目 | 现状 | 建议 |
| --- | --- | --- |
| 奖励 | 免费随机遗物 | 不要再作为随机事件；免费遗物交给宝箱节点 |
| 备选 | 只有离开 | 若保留事件形态，改成「失去 12 当前生命换遗物」 |
| 频率 | 2 次 | 从事件池移除，或只保留 1 个固定故事节点 |

免费遗物是当前最强的免费收益之一，和商店 145–220 金币的定价严重不符。更重要的是，它和本设计里的「镀金神像」定位重复：都是「用上限换遗物」。

推荐做法：

- **方案 A（推荐）**：把圣匣节点改成宝箱节点。宝箱本来就是免费遗物的入口，不需要再让一个事件承担同样的职责。
- **方案 B**：保留「遗忘的圣匣」作为固定故事节点，但改成「失去 12 当前生命，获得 1 件随机遗物；或拿 55 金币；或回复 10 生命」，并把它从随机池排除，避免和镀金神像同时出现。

这样事件池里的遗物来源仍然是稀缺的，玩家不会在一条路线上连续拿到多件免费遗物。

### 6.3 旅人的药剂

这个事件可以保留为「安全事件」，但需要降低频率，并给一个小的风险选项：

- **收下药水**｜获得 1 瓶随机药水。
- **帮他试药**｜失去 6 生命｜获得 40 金币和 1 瓶随机药水。
- **只问路**｜回复 10 生命。

这样它既能作为低风险事件的代表，也能让玩家在「安全拿一瓶」和「冒险多拿 40 金币」之间做选择。

### 6.4 篝火

保持不变。篝火已经是「只能选一项」的合格模板，不需要再叠加成本。它和事件的分工是：

- 篝火：稳定的恢复/训练/强化，玩家可以规划。
- 事件：不确定的、有代价的、改变构筑的选择。

## 7. 工程实现建议

### 7.1 当前系统的限制

相关文件：

- `data/events/event_definition.gd`：事件模板与导出字段。
- `scripts/events/event_rewards.gd`：效果注册、奖励池、发奖。
- `scripts/events/event_session.gd`：候选固定、领取保护。
- `scripts/map/event_panel.gd`：事件界面与选项按钮。
- `scripts/map/fixed_map_config.gd`：地图节点校验与事件内容。

当前限制：

1. 一个选项只能有一个 `effect`，不能同时「删一张 + 强化一张」。
2. `heal` 和 `gold` 只允许正数，不能作为成本。
3. `choose_cards` 固定为两组各 5 张、各选 1 张，不能做单组三选一。
4. 没有删牌、复制、随机强化、概率结果。
5. 事件节点直接绑定固定 `event_id`，没有随机池。

### 7.2 推荐的选项结构

```json
{
  "text": "搬走神像",
  "cost": {"max_hp": 8},
  "effect": {"type": "random_relic"},
  "result_text": "神像比看起来轻。你走出空地时，身后的供品一件件倒了下去。"
}
```

如果要做「熔一张、强化一张」，推荐把 `effect` 扩展为 `effects` 数组，并保持旧字段兼容：

```json
{
  "text": "熔掉一张牌，强化另一张",
  "effects": [
    {"type": "remove_card", "count": 1},
    {"type": "enhance_card", "count": 1}
  ]
}
```

兼容规则：

- 读到 `effect` 时，自动包装成单元素 `effects`。
- 旧的 `heal` / `gold` / `leave` 字段继续有效。
- `cost` 在效果之前支付；如果效果没有合法目标，先中止并退款，不能扣了资源却拿不到东西。

### 7.3 需要新增的能力

| 能力 | 参数 | 用在哪 | 优先级 |
| --- | --- | --- | --- |
| 选项成本 | `cost.hp` / `cost.gold` / `cost.max_hp` | 几乎所有新事件 | P1 |
| 单组三选一 | `choose_cards.unit_offer` / `unit_picks` / `effect_offer` / `effect_picks` | 折旗、教官、兽穴、难民、骑士、亡灵 | P1 |
| 删牌 | `remove_card.count` | 祭坛、铁匠 | P1 |
| 最大生命变化 | `max_hp.amount` | 商队、古树、难民、亡灵、老兵墓 | P1 |
| 复制牌 | `duplicate_card.filter` | 双子兵营、镜湖 | P2 |
| 随机强化 | `enhance_random.count` | 沙盘、坠星 | P2 |
| 赌局 | `gamble.chance` / `win` / `lose` | 泥沼、骰子、角斗场 | P2 |
| 复合效果 | `effects` 数组 | 铁匠 | P2 |
| 事件旗标/连锁 | `set_flag` / `requires_flag` | 后续章节 | P3 |
| 战斗事件 | `start_battle` | 后续章节 | P3 |

补充规则：

- **复制牌**默认复制目标牌当前的训练/强化状态。如果首版觉得过强，可以改成复制基础版本，但必须在选项文案里写清楚。
- **随机强化**只从「还能强化」的牌里抽；没有合法目标时，选项直接禁用。
- **删牌**不能移除牌组最后一张牌；只剩 1 张时选项禁用。

### 7.4 选项成本的规则

- **当前生命成本**：不能把生命扣到 0；至少保留 1 点。生命不足时按钮禁用，显示「生命不足」。
- **金币成本**：金币不足时按钮禁用，显示「还差 X 金币」。
- **最大生命成本**：先扣最大生命，再把当前生命夹到新上限；最大生命不能低于 10。低于下限时按钮禁用。
- **最大生命增加**：最大生命和当前生命同时增加等量；选项里另写的回复量再叠加。例如「最大生命 +4，回复 10 生命」实际是最大生命 +4、当前生命 +14。
- **组合成本**：所有成本必须同时满足才可点；支付顺序为金币 → 当前生命 → 最大生命，避免中间状态出现负数。
- **结算顺序**：成本 → 效果（含最大生命变化）→ `heal` / `gold` → 结果展示；保证治疗以新的生命上限为界。
- **效果失败退款**：如果效果需要选择卡牌但没有合法目标，支付前就应该检测并禁用；不要先扣再报错。

### 7.5 界面改动

1. 选项按钮增加第三行成本摘要，例如「最大生命 -8」「支付 35 金币」「失去 12 生命」，用红色或暗金色区分。
2. 不满足成本的选项置灰，并在 `tooltip_text` 里写原因。
3. `choose_cards` 支持只显示一组牌；标题写「选择一张征召牌」或「选择一张战术牌」。
4. 删牌/复制复用牌组网格，增加「按类别筛选」和「取消」按钮。
5. 结算页显示实际变化：「最大生命 80 → 72」「金币 99 → 64」。
6. 赌局选项在点击前显示概率；结算时显示「成功 / 失败」和实际收支。
7. 预览模式仍然只操作副本，不写入本局。

### 7.6 分阶段落地

| 阶段 | 内容 | 事件 | 验收 |
| --- | --- | --- | --- |
| P1 | 成本、单组三选一、删牌、最大生命 | 01、02、03、06、09、10、17、20 | 8 个事件可在扩展后的事件工坊配置并试玩 |
| P2 | 复制、随机强化、赌局、复合效果 | 04、05、07、08、11、12、13、14、15、16、18、19 | 12 个事件完成，事件池可抽 |
| P3 | 旗标、连锁、战斗事件 | 后续章节 | 事件可以记住上次选择并回访 |

**建议先做 P1 的 8 个。** 它们已经能覆盖「生命换力量」「金币换服务」「删牌」「上限交易」「招募」五种核心体验，足以验证玩家是否接受「事件有代价」。

### 7.7 事件池与存档

- 事件在**进入节点时抽一次**，把 `event_id` 和内容快照写入本局状态；查看地图、牌组、退出重进都不能重抽。
- 事件内容继续使用开局快照，编辑工坊资源不影响进行中的本局。
- 同一局用 `seen_events` 记录已出现事件，抽池时排除。
- 事件完成后再写入 `completed_events`，用于统计和后续连锁。
- 如果抽到的事件不再合法（例如奖励池被清空），回退到保底事件，不要让节点无法完成。

### 7.8 验收用例

- 金币不足时，支付金币的选项不可点，且不会扣到负数。
- 当前生命为 1 时，生命成本选项不可点。
- 最大生命降到 10 以下时，选项不可点。
- 牌组只剩 1 张牌时，删牌选项不可点。
- 没有可训练兵种时，训练选项不可点。
- 三选一必须恰好选 1 张才能确认。
- 复制、删牌、强化都只影响选中的那一张牌。
- 事件只能领取一次；查看地图/牌组后返回不会重抽。
- 预览模式不修改正式牌组、金币、生命、遗物、药水。
- 事件池不放回，同一局不重复。
- 存档退出再继续，已抽到的事件不变化。

## 8. 平衡与试玩

### 8.1 先看这几个数

| 指标 | 目标 |
| --- | --- |
| 单局事件点 | 3–4 个 |
| 单局普通战斗 | ≥3 场 |
| 事件金币总收入 | 80–140（不含遗物/卡牌） |
| 单局直接遗物事件 | ≤1 次 |
| 单局复制事件 | ≤1 次 |
| 事件路线 vs 战斗路线进 Boss 生命差 | ≤8 点 |
| 单个选项选取率 | 15%–70%（离开除外） |
| 单局重复事件 | 0 次 |

如果事件路线明显更轻松，按以下顺序调：

1. 先提高事件的代价（生命/金币/最大生命），不要先砍奖励。
2. 再降低事件出现频率。
3. 最后调整稀有度权重和同类上限。

一次只动一个维度，保留版本号。

### 8.2 试玩记录

每个事件至少记录：

- 事件 ID、楼层、选项、是否离开。
- 选择前/后的生命、最大生命、金币、牌组张数。
- 选择前是否拥有相关兵种/遗物。
- 玩家在事件页停留的时间。
- 玩家对「这个选择是否值得」的一句话反馈。
- 本局最终是否通关、Boss 前生命。

### 8.3 需要观察的坏信号

- 某个选项选取率超过 80%：它大概率是严格更优。
- 某个事件的平均停留时间低于 3 秒：玩家在无脑点。
- 事件后金币超过 300：金币事件给多了。
- 玩家在 Boss 前满血：事件治疗/篝火叠加过多。
- 玩家不愿意选任何有最大生命成本的选项：成本太高，或收益不够直观。
- 玩家反复查看牌组才敢选：说明选项信息不够清楚，或者删牌/复制的目标太难评估。

---

## 9. 文案规范

### 9.1 标题

- 4–8 个字，具体名词或地点。
- 不剧透结果，不用「神秘的」「奇怪的」这种空词。
- 好例子：折断的军旗、沉默的祭坛、镀金神像、被俘的骑士。
- 坏例子：神秘事件、古老的宝物、旅人的考验。

### 9.2 正文

- 2–3 句话，80–140 字。
- 第一句给场景，第二句给冲突，第三句可以给一个具体的感官细节。
- 不在正文里写数值；数值放在选项上。
- 不写「你获得了……」，那是结果页的事。
- 少用形容词，多用名词和动词。

### 9.3 选项

- 第一行是动作，不超过 12 个字。
- 第二行是代价和收益，必须具体。
- 好例子：**接过军旗** / 最大生命 -8 · 三选一征召牌。
- 坏例子：**接受传承** / 获得一些好处。

### 9.4 结果

- 1–2 句话，回应选择，承认代价。
- 不要写「恭喜你」。
- 例：「神像比看起来轻。你走出空地时，身后的供品一件件倒了下去。」

## 10. 下一步

1. **先定 8 个 P1 事件**：01、02、03、06、09、10、17、20。把正文、选项、结果文案填进事件工坊。
2. **做 P1 系统能力**：选项成本、单组三选一、删牌、最大生命变化。先不加赌局和复制。
3. **改路线**：第 1 层固定教学事件；第 3 层减少事件密度；事件节点改「旅途奇遇」。
4. **跑 3 条典型路线**：事件多、战斗多、商店多各一条，记录进入 Boss 前的生命、金币、牌组。
5. **再决定 P2**：如果玩家已经觉得「事件有代价」，再加复制、赌局和随机强化；如果事件仍然太送，先调数值，不要加内容。
6. **美术分批**：P1 先做 8 张插画；未完成前用现有 4 张图或纯文字占位，不要把 20 张图作为上线前置。

## 附录 C：一页速查

- **玩家缺什么？**
  - 缺遗物 → 镀金神像、古树之心、哥布林角斗场、泥沼之手。
  - 缺最大生命 → 商队残骸、古树之心、难民队伍、亡灵低语、老兵之墓。
  - 缺牌组质量 → 铁匠的最后一炉、沉默的祭坛、沙盘推演、老兵之墓。
  - 缺兵源 → 折断的军旗、兽穴、双子兵营、被俘的骑士。
  - 缺钱 → 商队残骸、骰子赌局、哥布林角斗场。
  - 缺恢复 → 古树之心、旅人的药剂、泥沼之手。
- **什么时候放什么？**
  - 前 3 层：小交易、招募、治疗；不要放复制和遗物。
  - 4–6 层：删牌、训练、第一次赌局。
  - 7–9 层：遗物、复制、双强化、高额赌局。
- **什么不能做？**
  - 免费送遗物。
  - 免费送两张牌。
  - 让事件比战斗更稳定、更安全、收益更高。
  - 让玩家在信息不足的情况下失去最大生命。
