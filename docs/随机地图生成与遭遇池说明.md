# 随机地图生成与遭遇池配置

正式新局默认生成三幕随机路线。每幕有 15 个房间楼层，第 16 层为 Boss。每局只生成一次并保存结果；进入战斗、返回地图和继续存档都不重新生成。旧固定路线、地图工坊实战和旧存档继续可用。

## 生成规则

配置入口为 `data/map_generation/route_rules.json`。

| 字段 | 当前值或含义 |
| --- | --- |
| `enabled` | `true` 使用随机征途；`false` 沿用地图工坊正式固定路线 |
| `rooms` | 15 个房间楼层，Boss 额外占一层 |
| `columns` / `paths` | 7 列、7 条随机游走路径，第二条路径强制使用不同起点 |
| `rest_quota` | 随机投放 6–7 个休息点，末层强制休息点另外设置 |
| `unknown_quota` | 随机投放 10–14 个问号房 |
| `shops` | 商店目标数量 3 |
| `difficulties.normal.elites` | 普通难度精英目标数量 5 |
| `difficulties.hard.elites` | 困难难度精英目标数量 8 |
| `seed` | 空字符串表示每次新局自动产生独立种子；填入固定字符串可复现地图 |
| `difficulty` | 新局默认难度档，当前为 `normal` |
| `config_version` | 规则配置版本；修改规则时手动递增 |
| `event_pools` / `act_names` | 三幕分别使用的事件池与地图名称 |

路径只向相邻的更高楼层前进，普通相邻节点列差不超过 1，避免 X 形交叉。路径接触时合并为同一个节点。第 1 层全为普通战斗，第 9 层全为宝箱，第 15 层全为休息点，全部路线通向第 16 层 Boss。

类型投放按休息、商店、精英、问号的配额队列进行三轮尝试，剩余节点补为普通战斗。第 1–5 层不安排额外休息或精英；第 13–14 层不安排休息。精英、休息、宝箱、商店避免父子同类型；同一分叉的休息、战斗、问号、精英、商店尽量避免重复。

剪枝比较同一分叉到首次汇合的类型序列，保留随机选择的一支，删除另一支的独立走廊节点，并清理不可达节点。共享分叉入口与强制行受到保护。剪枝和配额修复最多交替三轮，每轮剪枝最多 50 次；局部路径枚举另有工作量上限，不会无限搜索整张地图的全部路线。

配额沿用软目标：修复不会破坏相邻限制，也不强行增加节点。极端种子可能不足，差额记录在地图 `generation.quota_shortfalls`。强制行和到 Boss 的连通性为硬约束。休息目标是初始额外投放量，修复阶段按总数检查，与报告描述的语义一致。

## 种子和难度

地图随机使用独立的 `RandomNumberGenerator`，从种子字符串和幕编号派生随机流，不消耗战斗、商店或事件随机数。遭遇分配另有独立派生流，避免内容抽取改变地图拓扑。相同种子、规则、遭遇配置、难度和生成器版本产生相同地图；没有实现原作 PRNG 或原作种子的逐位对应。

主菜单开始征途会读取规则。也可通过启动参数指定种子与难度：

```text
-- --map-seed=MY-ROUTE --map-difficulty=hard
```

代码入口支持 `RunManager.start_new_run(null, "MY-ROUTE", "hard")`，返回空字符串表示成功。配置或生成失败时保留原有征途，主菜单显示错误。

Godot 地图工坊新增种子输入、难度选择和“生成随机路线”按钮，按“应用到第几幕”选择生成目标幕。生成结果可编辑、保存 JSON，或直接启动当前路线实战。随机征途启用时，“应用到游戏”仍保存固定路线，但正式新局优先随机规则；要使用固定路线，应关闭 `enabled`。HTML 工坊可往返编辑生成后的固定 JSON，并保留种子元数据与问号候选。

## 战斗遭遇配置

`data/map_generation/encounters.json` 按文件顺序采用第一条匹配的规则。将更具体的幕或难度规则放在通用规则之前。

```json
{
  "acts": [2],
  "phases": ["middle"],
  "kinds": ["elite"],
  "difficulties": ["hard"],
  "levels": [{"level": "level_elite_late", "weight": 1}],
  "reward_config": "res://data/battle_rewards/elite.tres"
}
```

`early` 为第 1–5 层，`middle` 为第 6–10 层，`late` 为第 11–15 层，`boss` 为 Boss；改变总房间数时按三等分计算。`kinds` 支持 `normal`、`elite`、`boss`。每个候选填写真实的 `level_` 文件名，权重为正整数。可在规则指定奖励模板；没有指定时读取关卡奖励。

开局检查三幕、各难度、各进度均有对应候选，关卡存在且有效。生成时把抽中的关卡编号与战斗奖励写入节点，再冻结进本局地图。不会等到进入某层才发现空遭遇池。第一版三幕暂时复用现有第一章战场资源，尚不代表第二、三幕的敌人和数值已完成制作；可逐幕追加专用规则。

新增 `level_elite_mid.tres`、`level_elite_late.tres`，分别基于现有中后期战场的波次制作独立精英关卡。奖励采用 `data/battle_rewards/elite.tres`，具体数值以当前资源为准。

## 精英和问号房

保留原类型编号：0 战斗、1 事件、2 休息、3 Boss、4 宝箱、5 商店；末尾追加 6 精英、7 问号房。已有 JSON 的类型含义不变。

地图将旧事件与问号房统一显示为“随机事件”，共用原来的问号图标与同一条图例。精英使用原首领头像，普通节点为 88 像素。路线底部以 320×240 的出征营地连接所有起始房间，顶部幕终 Boss 使用 360×270 的专用首领堡垒插画；两者均不加入图例。营地仅是公共出发标记，不增加房间、楼层或存档节点；第 1 层仍可直接选路。Boss 的点击区域、选中红圈、完成旗帜和连线留白均随大图案调整。两张透明底墨线素材位于 `assets/ui/map/route_start.png` 和 `route_boss.png`，生成提示词见同目录的 `route-endpoint-prompts.json`。

问号房的 `unknown_options` 保存普通战斗、事件、宝箱、商店和精英五类候选内容。首次进入前抽签，解析后的实际类型走已有战斗、商店或事件入口，图标同步揭晓。默认基础概率为普通战斗 10%、商店 3%、宝箱 2%、精英 0%，剩余为事件。未命中的类型按基础概率累加，命中后重置；累积总和超过 1 时按非事件候选比例归一化。前一房间是商店或所有后继节点均为商店时，本次禁抽商店。

概率按幕独立。首次结果、解析后内容和当前未完成节点在打开房间前进入存档检查点，重进不会重掷，也不能读档后选择另一支。问号商店保存初始化种子，恢复节点时沿用该商品随机入口。尚未统一整局的事件、战斗奖励与普通商店随机，地图种子不承诺这些内容首次抽取完全一致。

现有第一章事件池按 2–9 层设计。随机地图把事件抽池进度映射回该范围，实际节点楼层及事件日志仍记真实层数；抽池按幕去重，资源类事件次数限制继续按整局执行。池不足时沿用现有兜底事件。

## 存档

保存 `active_map`、`active_act_maps` 及进度，并新增：

- `map_seed`、`map_generator_version`、`map_config_version`、`map_difficulty`。
- `resolved_rooms`：以“幕编号:节点编号”为键的问号首次解析结果。
- `unknown_room_odds`：各幕的问号累积概率。

每幕的 `generation` 另含遭遇配置版本、剪枝统计、配额差额与问号基础概率。继续存档直接恢复这些结果，生成规则被修改或不可用也不会重新造图。实际战斗仍需项目内对应的关卡和场景资源。旧 v1/v2 存档缺少新字段时采用空元数据，继续使用原路线。

## 验证

```text
python tools/maintenance/run_checks.py --checks random-map map-editor fixed-map three-act map-direct-apply events treasure shop battle-rewards config-cache --label random-route --timeout 120
python tools/maintenance/run_checks.py --checks random-map-sweep --label random-route-10000 --timeout 180
```

测试使用隔离用户目录。随机地图检查覆盖种子一致性、难度和遭遇绑定、五种问号结果的真实地图分发、问号锁定、独立引擎进程恢复、旧存档兼容、工坊 JSON 往返和真实精英战斗结算。

初次 10000 个种子结构抽样全部通过，覆盖三幕与两种难度；其中前 100 张另做完整资源校验。137 张存在软配额差额，已保留在生成诊断字段中。这是结构与接入验证，尚未完成 15 房间长度下的整局战损和经济平衡试玩。
