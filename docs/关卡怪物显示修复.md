# 关卡怪物显示修复

2026-10-10 已修复部分关卡进入后看不到怪物和手牌的问题。

## 原因与范围

`level_107_2.tres` 的波次配置完整，五波怪物数量分别为 **4、5、5、8、5**。
怪物实际会生成并登记到战斗系统，但它使用的 `battle_006.tscn` 把父节点
`Entities` 保存为 `visible = false`，导致整队怪物及后来部署的己方单位不可见。
同一场景还隐藏了 `CardUI`，因此手牌、敌方生命与开打按钮也不会显示。

全量检查发现以下四个关卡有相同问题：

| 关卡 | 战场 | 各波怪物数量 |
| --- | --- | --- |
| level_107_2 | battle_006 | 4、5、5、8、5 |
| level_108_1 | battle_007 | 4、6、7、2、8 |
| level_108_2 | battle_008 | 5、6、6、5、9 |
| level_110_1 | battle_009 | 5、6、6、6、9 |

尚未被关卡引用的 `battle_005.tscn` 也保存了相同隐藏状态，一并修复。
其余关卡的怪物配置和实际生成数量检查通过。`level_002` 第三波是明确配置的空回合，保留原有规则。

## 修复

- 清理 `battle_005` 至 `battle_009` 中实体、战斗界面等节点的误隐藏覆盖，恢复继承场景的正常显示状态。
- 在 `scripts/battle/battle_scene.gd` 的开场初始化中，显示 `Entities`、`TeamA`、`TeamB` 和战斗 UI，兼容以后复制或编辑场景时残留的隐藏状态。
- 结算面板仍由自己的开场和胜负逻辑管理。
- 新增 `tests/level_spawn_test.gd`，接入现有测试入口和维护检查命令。

## 验证

全量刷怪回归检查 **14 份关卡配置、9 个战场、65 个非空波次、164 个实际回合**，
包含首轮、后续波次、空回合、两次循环及非循环耗尽后的末波复用。
检查数量、敌方登记、精灵实际可见性、坐标、初始生命及成长属性、重复信号去重。
另外故意隐藏场景必要节点，验证开场自动恢复；使用第一章实际路线，通过游戏外壳进入四个受影响关卡，
验证首轮抽牌和查看地图后返回战斗。

结果：**4029 项检查全部通过，零失败，零引擎错误**。

以下九组关联检查也全部通过：战斗架构、整局游戏流程、波次循环、波次单次增益、波次编辑器、
波次预览、全项目资源加载、固定路线导入、战场镜头。

已通过 GPU 实际渲染确认 `level_107_2` 首波四怪和手牌界面正常显示。
