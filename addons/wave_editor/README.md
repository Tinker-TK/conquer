# 波次编辑器

在 Godot 顶部选择 **波次编辑器**。插件已启用；更新后如界面没有刷新，请重新打开项目。

## 关卡与保存

- 左上选择已有的 data/levels/*.tres；“打开…”可选择项目其他位置的 BattleLevelConfig。
- “新建”创建空白草稿。在“地形”按钮上拖入文件系统面板中的 battle_001.tscn 等战斗场景，也可点击浏览。场景必须继承正式 battle_scene，保留 Level、Entities/TeamB、BattleRoundManager 和 configure_level。
- 输入关卡名后回车或移开焦点提交；“循环波次”直接设置 repeat_waves。
- “保存”写回当前路径；新关卡需要选择 .tres 文件名。“另存为”只允许新文件，避免覆盖其他关卡。
- 继续使用 BattleLevelConfig.waves: Array[PackedScene]，每个回合独立内嵌在关卡资源中。空回合保存为 null；保存和实战要求有地形及至少一个非空回合。
- 保存比较读取时与写入前的 SHA-256，再写入同目录临时文件，保留原关卡 UID，复查指纹后重命名替换。外部修改、删除或另存目标已存在时停止保存；可取消、另存为或明确放弃草稿后重读。不会提供强制覆盖按钮。

## 撤销和未保存保护

新增、删除、排序、复制回合，增删、替换、复制怪物，整组拖动，以及地形、名称、循环设置都可撤销和重做。一次完整拖动是一步；切换关卡会清空历史。回到保存点时“● 未保存”消失，另存为后仍可撤销。

切换、新建和重读前提示“保存并继续 / 放弃修改 / 取消”。禁用插件时也保留保存对话框；取消禁用保存流程会重新启用插件并提供草稿恢复。

退出项目使用 Godot 原生未保存提示；“保存全部”也保存当前关卡。未命名、无效配置或外部冲突无法写回目标时，保存 user://wave_editor_recovery.tres，下次启用时提供恢复。恢复保留原始文件指纹，因此不会绕过外部修改保护。若恢复文件也写入失败，会明确报错，请取消退出并另存为可写位置。

编辑操作完成后也写入恢复草稿；明确放弃或成功保存时删除恢复文件。撤销历史本身不跨重启保留。

## 站位与批量操作

- 左侧增删、复制回合，用 ↑ / ↓ 调整顺序。
- 搜索框按中文名称或英文文件名筛选敌方怪物。
- Ctrl/Shift 点击或在空白处拖框多选；下方清单也支持多选。“添加”放入新怪物，“复制 / 替换 / 删除”作用于整组选择。
- 拖动任一选中怪物移动整组；开启网格吸附后，以首个选中怪物对齐世界网格，其余保留相对位置。格距可选 8–128 像素。
- 滚轮围绕鼠标缩放，中键拖动平移，“适应窗口”按实际地形范围恢复全景。支持超出 1920×1080 和包含负坐标的大地图，切换地形时自动居中；循环背景不计入地图大小。
- 敌方建议区域使用烘焙导航的右半边，与正式友军的左半边部署对应。没有烘焙导航时明确显示“导航未知”。
- 区域检查依据脚底位置；重叠提示依据实际碰撞形状的保守外接圆，不等同于完整寻路或精确碰撞模拟。越界、重叠以橙色及 ! 标记，下方清单显示原因。提示不阻止保存。
- 实战出兵时，默认 Floor Id 1 的怪物按站位自动识别最上方地表，直接摆在二至四层也会使用对应的绘制、碰撞和导航楼层。旧阵型无需重摆或重新保存；显式配置的 Floor Id 2～4 保持原值。需要固定桥下楼层的阵型，可在战场 Entities/TeamB 关闭 Auto Detect Spawn Floor，完全使用各单位的 Floor Id。

快捷键（焦点不在文字输入框时）：Ctrl+Z 撤销，Ctrl+Y / Ctrl+Shift+Z 重做，Ctrl+S 保存，Ctrl+A 全选怪物，Ctrl+D 复制怪物。

## 播放与实战

“播放下一回合”从第 1 回合逐次展示阵型，明确显示空回合；循环关卡显示循环次数。记录列出每回合怪物种类、数量和累计出场总数，保留最近 200 条。编辑内容变化或切换关卡后重置记录。

“从当前回合启动实战”把当前草稿写入独立的 user://wave_editor_playtest.tres，并启动插件测试场景。真实战斗使用选中回合号、完整波次数组和正式刷怪代码；后续有限/循环行为保持一致。新开局使用初始血量和牌组，不恢复之前回合的存活单位、手牌或战斗状态。Godot 的“运行前保存”设置可能触发保存全部，保存仍经过冲突检查。已有游戏在运行时须先停止。

实战天气使用关卡配置；天气留空时沿用战场场景的预设，基础战场默认晴天。关卡资源中指定的雨天、雪天，以及战场场景中单独设置的天气仍会生效。

## 指定区间循环与单位成长

1. 勾选“循环波次”，输入起始波 **3**、结束波 **5**，点击“应用范围”。结束波为 **0** 时表示当前末波，旧关卡仍默认循环整个数组。
2. 选择原始第 3 波，点选一个单位，在“单位增益”选择“循环成长”和“攻击力”，填 **3**，点击“应用到选中”。支持多选批量设置，也可选择最大生命或防御；不同属性可以同时配置。“清除此效果”只清除当前属性，或输入 0 清除。
3. 保存后实际出兵顺序为 **1、2、3、4、5、3、4、5、3……**。循环结束波之后的原始阵型不再出场，列表会标为“不出场”；循环范围按当前波次编号解释，增删/排序后应重新检查范围。
4. 第 3 波首次出现不加成；第 6、9、12 回合该单位分别增加 **3、6、9** 点攻击力。同波次其他未配置的单位不受影响；前面已经出场的单位也不会被追溯修改。
5. “播放下一回合”同时显示实际回合、引用的原始波次和重复次数，单位清单及记录显示累计加成。从第 12 回合的循环预览启动实战，会保留真实第 12 回合号和 +9 加成；手动点选原始波次则回到它的首次出场。

范围与单位效果均支持撤销/重做、保存重读和草稿恢复。复制单位或回合、替换兵种会保留单位的成长配置。加成只作用于每次新生成单位的独立属性副本，不修改共用的怪物基础资源。

关闭循环时维持当前游戏的 HP 战斗规则：原始列表耗尽后重用最后一个非空阵型，不叠加循环效果。编辑器的非循环顺序预览仍在原始列表末尾停止。

专用验证：`Godot --headless --path . --script res://tests/wave_loop_test.gd`。覆盖 3–5 循环、空波次、单波循环、旧资源兼容、单位成长隔离、撤销/复制/替换、保存重读和真实战场初始化。

## 单次增益

选中一个或多个单位，在“单位增益”里选择 **单次增益**，选择攻击力、最大生命或防御，输入固定加成后点击“应用到选中”，再保存关卡。每个新生成的单位在出场时施加一次，首次出场就生效；再次出场仍是同样的固定值，不按循环次数累积。关闭循环的关卡也可配置。

单次增益和循环成长可以同时设置。例如单次攻击 **+5**、循环攻击 **+3**，第 3 波在 3～5 循环中于第 3、6、9、12 回合的总攻击加成分别为 **5、8、11、14**。单次增益不会在已经出场的单位身上重复施加。

“清除此效果”或输入 0 只清除当前模式、当前属性，其他增益保留。批量设置、清除、撤销/重做、复制单位/回合、替换兵种、保存重读和恢复草稿都保留两种配置。

实战中增益显示在单位现有的 Buff 栏：同属性合并图标，悬停分别列出“波次单次增益”和“循环成长”的来源与贡献。满血时仍显示 Buff；增益保持到单位死亡或本场战斗结束。

专用验证：`Godot --headless --path . --script res://tests/wave_spawn_effect_test.gd`。
