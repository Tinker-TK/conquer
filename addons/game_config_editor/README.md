# Godot 游戏配置编辑器

Godot 顶部打开 **游戏配置**，入口与“波次编辑器”“地图工坊”并列。插件已在 `project.godot` 启用；首次安装或编辑器未显示新页签时，重新打开项目。

首次打开页签时自动读取配置，并等待编辑器完成资源扫描。尚未载入时会明确显示状态，校验、导出和新增行列暂不可用；“重读”、导入和工具设置仍可使用。初次读取失败时保留具体错误，修正问题后可点击“重读”或重新切回页签重试，避免空文档被误报为“合集版本不支持”。

左侧七个分类：卡牌效果、卡牌效果明细、己方单位、敌方单位、技能、遗物、药水。右侧每行对应一个实际 Godot 资源，每列对应一个导出属性；横向滚动查看更多字段，搜索按名称、路径和字段内容筛选。点击行名称查看实际文件、实现脚本及关联配置，点击“在检查器中打开”定位资源。

鼠标停在表头或参数格上可查看中文用途说明，包含单位、取值含义与生效条件。说明自动读取资源脚本的 `##` 文档，继承参数也会显示；新增字段填写的说明同时保存到脚本，供原生检查器使用。全系统检查范围见 [参数悬停说明检查](../../docs/参数悬停说明检查.md)。

技能表按“单位名称、技能名称、解锁强化等级”排列。单位名称根据单位的主动技能列表和防守反击自动显示，只读；共享技能会列出全部关联单位，也可按单位名称搜索。解锁强化等级使用 JSON 整数数组：`[0,1]` 仅在未强化和强化一次时生效，`[0]` 只在未强化时生效，`[1]` 只在强化一次时生效，`[2]` 只在强化两次时生效；`[]` 表示始终不生效。每项为 0～99 的整数，等级不在数组中时该技能失效。判定使用每张单位卡自己的强化次数，主动技能和防守反击、真实出场和卡牌详情共用此规则。需要替换技能时，把旧技能配置为 `[0]`、新技能配置为 `[1]`，并将两者都加入单位技能列表。默认普通技能为 `[0,1]`；现有强化后获得的技能已设为 `[1]`。配置等级 2 或更高时，请同时将对应单位的“可强化次数”设为至少该等级。

## 编辑与保存

- 文本和数字回车或移开焦点提交；枚举和开关选择后立即进入草稿。黄色字是修改，红色字是无法解析的输入。长说明支持多行。
- 从 Excel 复制多行、多列，点击目标格子后 Ctrl+V。粘贴跳过只读格子，整块解析成功才提交，一次撤销即可恢复。
- “保存并应用”先读取磁盘当前配置，再检查类型、范围、枚举、动画与命中帧等规则。外部改动与草稿基线冲突时拒绝覆盖。成功后自动备份、写入并由 Godot 回读验证；回读失败撤销本工具的写入。
- “校验”执行同样的检查但不写入。“重读”会重新读取当前游戏配置，有未保存修改时可保存并继续、放弃或取消。
- 备份在 `.maintenance/config_catalog_backups/时间戳/`；原始文件与项目相同相对路径，`changes.json` 记录新增和修改。新建文件回滚时删除。
- 成功保存会刷新 Godot 资源目录和标准 HTML 合集，重新运行游戏场景后使用新配置。检查器内另外打开的资源或脚本如有修改，应先保存，避免之后用旧内容覆盖配置表的写回。

## 新增行与字段

“新增配置行”复制同类的已保存模板，填写英文 snake_case 标识和可选显示名。新行的数值可以继续编辑，也可移除或撤销。保存时创建 `data/对应类别/新标识.tres`；单位同时生成 `scenes/units/新标识.tscn`，绑定新数据并沿用模板的动画、图片与技能。

卡牌效果明细新行会追加到模板所在卡牌的内嵌效果列表。若给刚创建的卡牌增加效果，先保存新卡，再在明细表复制它的效果。新单位、卡牌、遗物、药水或技能仍需被关卡、卡组或其他资源引用，才会在游戏中出现。

“新增字段列”支持整数、小数、文本和开关，保存时添加对应资源脚本的 `@export var`，并为该类资源写入每行值。己方和敌方共用 UnitData，新增单位字段同时出现在双方表中。尚未应用的列可用表头“移除新列”取消。中文名称、说明存于 `tools/config_catalog/custom_fields.json`。新增存储字段只有被玩法逻辑读取后才会影响战斗。

## 草稿与交换

撤销 / 重做覆盖格子编辑、批量粘贴、新增或移除行列。输入框外使用 Ctrl+Z、Ctrl+Y 或 Ctrl+Shift+Z；Ctrl+S 保存并应用。Godot 的“保存全部”也会应用本面板草稿。

编辑后保留 `user://game_config_editor_recovery.json`；退出和禁用插件时也保留草稿。下次开启提供恢复选项。红色格子的原始文本同样保存，恢复后需修正再应用。撤销历史不跨编辑器重启保存。

“导入合集…”读取已有 HTML 或 JSON 的嵌入数据，不执行 HTML 脚本；“导出 HTML / JSON…”保存可继续编辑的合集。与原 `docs/game_config_catalog.html` 工具共用格式，后续可以继续交给 Codex 读取或应用。

## 开发与验证

界面在 `editor.gd`，草稿与历史在 `document.gd`，线程桥接在 `bridge.gd`，中文字段显示在 `labels.gd`。写回复用 `tools/config_catalog/catalog.py`，通过本机进程执行，不需要浏览器或 HTTP 服务。自动寻找现有的 Codex Python 运行时，也支持系统 `python`；换机器后若找不到，可在“工具设置…”选择 Python 可执行文件。

运行时使用当前 Godot 可执行文件进行资源回读，因此插件与 HTML 工具保持同一套校验规则。

```text
Godot --headless --path . --script res://tests/game_config_editor_test.gd
Godot --headless --path . --script res://tests/game_config_editor_loading_test.gd
python tools/config_catalog/test_catalog.py
node tools/config_catalog/test_ui.cjs
```

原生测试读取实际资源但不应用游戏数值，导出和恢复文件放在测试专用 `user://` 路径。Python 测试的读写全部在隔离夹具中，覆盖备份、冲突、回读失败回滚和编辑器桥接应用。实际配置导出入口在 `addons/game_config_editor/config_catalog_export.gd`，与回归测试分开保存。中文布局可在顶部“游戏配置”面板检查；旧的一次性截图脚本已归档，见 [项目清理记录](../../docs/项目清理记录.md)。
