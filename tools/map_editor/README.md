# 固定路线地图编辑器

双击 `index.html`，使用现代浏览器打开。单个 HTML 文件，不需要服务器或安装依赖。

现在也可直接在 Godot 顶部“地图工坊”页签编辑同一份路线，操作方式与项目的波次编辑器一致。支持打开已有 JSON、拖动连线、选择项目战斗关卡、编辑事件奖励、保存/另存为、撤销与实战检查，详见 [原生地图工坊说明](../../addons/map_editor/README.md)。

## 使用

1. 初次打开显示十层示例。可以直接修改，或点击“新建”。
2. 选择左侧节点类型，点击地图空白处添加。拖动节点调整横向位置和所在层。
3. 在右侧编辑编号、名称、类型及战斗关卡或事件内容，勾选出发点。第 1 层新节点默认是出发点。
4. 点击“连线”，依次点击源节点和更高层的目标节点。允许分叉、汇合和跨层；不允许重复连线及向下连线。
5. 点击节点查看并删除其出边，或在选择模式点击路线后删除。删除节点会同时清除关联路线。
6. 检查右侧提示，使用“路线试玩”从出发点逐步前进。
7. 导出 JSON 留存；导入可恢复编辑。存在路线问题时可确认导出草稿。

浏览器会自动保存当前地图；不同浏览器或文件位置可能使用不同存储空间，重要配置请导出。撤销/重做最多保存近期 80 次普通编辑，关闭页面后历史不保留。导入、载入示例、新建也支持撤销。

## 配置约定

- `schema_version: 1`：文件格式版本。
- `mode: "fixed"`：固定路线，预留未来其他地图模式。
- `name`、`floors`：地图名称与总层数（2–30）。
- `starting_ids`：可选出发节点 ID。
- `locations`：节点列表，每个节点包含 `id`、`title`、`type`、`event_id`、`floor`、`map_pos`、`next`；非战斗节点额外包含 `event`。
- `id` 自动命名统一为 `floor_03_01`：创建时的层号和该层可用序号，均至少两位。新建节点和新示例使用同一规则并避开已有编号。移动节点、修改类型不会自动改名；现有草稿和导入配置保留原编号。手动修改编号会同步更新地图的出发点与路线引用。
- `type`：0 战斗、1 事件、2 休息、3 Boss、4 宝箱、5 商店，与当前游戏枚举一致。
- `map_pos`：归一化 `{ "x": 0.5, "y": 0.93 }`；x 为横向位置，y 根据层级从 0.93 到 0.07 自动计算。
- `next`：目标节点 ID 数组，方向从低层到高层。

## 导入到游戏

宝箱节点使用固定规则，无需填写事件或战斗关卡。玩家进入后点击宝箱图片或“打开宝箱”，立即从 `data/relics/` 中随机获得一件有效且未持有的遗物；名称和效果显示在开箱结果中，点击“继续前进”完成节点。已停用的基地防御遗物不参与抽取；遗物全部拥有时显示说明并允许继续。内置地图和工坊示例的第五层已加入宝箱。旧路线可将节点类型改为“宝箱”后重新导出导入。

1. 在编辑器中点“导出 JSON”，建议保存到项目 `data/levels/` 目录。浏览器自动保存的草稿不会被游戏直接读取。
2. F5 启动游戏，在主菜单点“导入路线 JSON”，选择刚导出的文件。
3. 主菜单显示路线名称、层数和节点数后，点击“开始游戏”。节点位置、类型、出发点和连线全部使用该配置。
4. 导入的路线会保存一份到 Godot 用户数据目录的 `imported_fixed_map.json`，重启后仍有效。点击“使用内置地图”恢复原十层地图。

游戏在新局开始时复制配置，战斗返回不会丢失路线。修改 HTML 中的地图后，需要重新导出、在主菜单重新导入并开始新局；不会覆盖正在进行的冒险。导入失败时会显示原因，并保留之前成功导入的路线。

游戏只接收可游玩的路线：所有节点可从出发点到达、路线向更高层和更上方前进、所有终点为 Boss 且 Boss 没有出边、节点名称不为空、战斗关卡有效、事件描述及两个选项配置完整。编辑器导出的不完整草稿需要先修复，才能导入游戏。通关由完成终点 Boss 决定，与路线是否恰好十站无关。

战斗/Boss 节点在“战斗关卡（文件名）”中直接填写 `level_001`，游戏读取 `res://data/levels/level_001.tres`；填写 `level_002` 则读取同名关卡。不加路径或 `.tres` 后缀。配置保存在 JSON 的 `event_id` 字段，GameSession 不再提供额外绑定。关卡不存在或无效会拒绝导入，不会替换成默认战场。新增关卡可在 `data/levels/` 创建 `level_` 开头的 BattleLevelConfig 资源，再填入其文件名。

普通事件和休息节点直接编辑“显示名称”（事件标题）、“事件描述”和两个选项。每个选项可填写按钮文字、回血量、金币奖励，奖励均为 0–9999 的整数，填 0 表示不发放。只有玩家选中的选项会结算，回血不超过生命上限；不选中或仅查看地图不会发奖。当前不支持扣费、扣血或卡牌/遗物奖励。

新建休息节点预填篝火四选项模板：休憩整备（默认回复最大生命的 30%）、训练兵种卡、强化非兵种卡、离开。新建事件节点预填废弃兵营模板（搜刮获得 15 金币）。描述和选项保存在节点的 `event: { description, choices: [{text, heal, heal_percent, gold, effect}, ...] }` 字段；支持 2–8 个选项，`heal_percent` 为 0–100 的最大生命回复百分比，`effect.type` 可以为 `train_unit` 或 `enhance_card`。旧的 campfire / abandoned_camp 配置在缺少 event 时补齐模板；已有明确 event 数据始终优先。

旧的 battle_01、boss_01 等间接战斗编号已停止使用。请在工坊将战斗/Boss 改为实际的 level_001、level_002 等关卡文件名，再导出并重新导入。原 GameSession 的三组绑定已清理。

导入限制为 2 MB、500 个节点。非法字段、重复编号或不存在的引用会被拒绝；不可达节点、反向边及终点异常会在路线检查中提示，便于修复草稿。试玩只验证路线可选性，不运行实际战斗和事件。

运行数据逻辑检查：`node tools/map_editor/check.cjs`。

运行游戏接入检查：`Godot --headless --path . --script res://tests/fixed_map_import_test.gd`。该测试应使用独立的测试用户数据目录，避免与正在运行的游戏同时写入选择文件。
